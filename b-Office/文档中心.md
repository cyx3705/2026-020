# HistoryJanus 文档中心

本目录按 AIReady 元文档规范分为现行合同和历史资料。源码、运行时事实与 `current/` 共同构成当前基线；`history/` 只用于追溯。

## 现行文档

- [`项目概览.md`](./current/项目概览.md)：目标、边界、状态、交付物和依赖。
- [`技术合同.md`](./current/技术合同.md)：模块化需求、系统边界、关键流程和生成物规则。
- [`有效决策.md`](./current/有效决策.md)：仍影响后续实现的架构与发布决策。
- [`验证合同.md`](./current/验证合同.md)：日常、正式发布、部署和人工验收门禁。
- [`指令优化规范.md`](./current/指令优化规范.md)：跨模块命令命名合同（`域.类.方法` 全小写）与 Janus 3.5.0 映射样板。

只有单份文档已明显影响维护时才拆专题，不按每个功能或版本持续增加现行文件。

## 指令说明书

宿主 6.1.0（DEC-072）起没有消费文档。别的模块要知道 Janus 的指令怎么调用，读注册时的自描述：
`diana.docs.read domain=janus`；改指令时把 Summary / 参数说明 / Example 写到照抄能跑，并用 `diana.docs.audit domain=janus` 自查。

## 目录规范

| 级别 | 本项目用途 |
| --- | --- |
| `b-*` | 源码、验证、文档、素材和本地发布事务等项目组成 |
| `z-*` | 已通过正式门禁、供其他项目复用的最新消费快照 |

`z-Publish` 根只保存当前一个 `HistoryJanus-vX.Y.Z/` 候选和 `history/` 历史包；该版本化目录是受 manifest 和 SHA-256 约束的唯一正式消费区。部署到 AppShell Modules 目录只是运行同步，不构成第三层发布区。

## 历史资料

`history/` 保存已经结束的 V 版本施工记录，不是当前项目真值。常规规划、实施和验收只读取 `current/`；需要追溯时只读取用户明确指定的最小历史文件。历史与源码、测试或现行合同冲突时，以可验证的现行事实为准。
