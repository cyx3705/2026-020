## 取舍

- **一项目一仓。** 库根默认 `C:\OneHistory\HistoryClio`（`proj.libraryroot`），只扫直接子目录；已登记项目的 `.git` 必须是目录，仓内默认分支 `main`。新建是复制模板工作树后 `git init -b main`，不 `clone`，免得把模板历史带进新仓。受保护的是模板项目名 `0000-000-Template`，不是 `main`。指向旧 `HistoryVesta.git/worktrees` 的 `.git` 文件只诊断，不自动删。
- **新建不继承根下 z/Z 文件夹。** 选择性备用模板放在模板仓的 z 级目录里（`0000-000-Template` 的 `z-Unused`）。`janus.proj.create` 复制工作树时整段跳过；要用哪一块，再从模板仓复制进项目。归档后的拉取仍恢复该项目自己留下的 z/Z 内容，那不是继承。
- **Janus 不拥有 AI 工作区，也不发布。** 工作区与正式快照由宿主 `vulcan.dev.*` 独占。不注册 `janus.aiworktree.*`，不引用 Apollo 程序集，不复制宿主运行库，不把 CLR 类型当跨模块 API。
- **没有自己的窗口。** 常驻三页：`overview`（项目表，竖在左侧）、`projops`（项目操作，中间主页面）、`graph`（底部），`scene=HistoryJanus`；入库规则 / LFS 规则 / GitHub 是三张平时不露面的页（`janus-rules` / `janus-lfs` / `janus-github`），由项目操作页第二行按钮经 `aurora.ui.float` 浮成弹窗，每次打开都按节点重取。分支历史不是子页，是项目操作页面板下面的常驻表格。预览和提示一律 `aurora.ui.dialog`。用户已保存的各场景布局优先（新落位要 `aurora.scene.reset scene=HistoryJanus` 才看得到）；刷新不得打开别的场景的页面。已退役的页面 ID `tree` / `meta` / `history` 不得恢复。
- **分支控制只管本地分支。** 项目操作面板第三行是选项条（Aurora `choices`）：只摆当前分支、main 与还没并入 main 的分支，合并完的不再摆（用户定）；刚分出来、一次都没提交过的分支也指向 main 历史里的提交，`--merged` 会列它，但它是「还没开始」不是「合并完了」，照样摆出来（按 reflog 只有建分支那一条判定）；当前分支排第一、默认选中。按钮上的字最多 10 个（5.16.2，用户定）：超长截短补「…」，当前分支写「名称·当前」也算在 10 个里，全名悬停可见。点一项发上 `janus.branch` 通道，下面历史表按它取数；右键一项是切换 / 合并到当前 / 从此分出 / 删除（菜单的 `{value}` 是被右键那一项）。切换就是把项目这唯一一份工作树换到另一条分支；切换与合并遇到脏工作树先拒绝、直接弹提交窗口，人提交或丢弃后接着做。合并有冲突就 `merge --abort`，什么都不动。main 与当前分支不能删，未并入当前分支的要强制删（宿主确认会写明独有提交会丢）。生命周期作用在项目上，不看工作树停在哪条分支（5.16.4，用户定）：main 比 origin/main；其余没并入 main、也不是开发管线 `ai/` 开头的本地分支，各比 origin 上的同名分支。顺序是：有未提交内容→提交；main 分叉或落后、当前分支落后远端→同步；main 领先或有分支没推→推送（推送把 main 和这些分支一并推上去）；远端有本地没有的分支→同步；全部一致但未校验→同步；校验过→归档。停在别的分支上也能同步：main 不在工作树上时带旧值直接快进引用；只有 main 分叉时要先切回 main。归档记录与拉取都按 main。
- **刷新只管远端，本地改动无感对齐（5.16.2，用户定）。** 「刷新」按钮 = fetch 全库再重读。工作树变脏、新建项目、提交、切分支这些本地变化不用按刷新：界面取过总览后监视项目库目录，哪个项目有改动，停手 0.8 秒后只按本地引用重读那一个项目（不 fetch），读数真变了才安静地（不进控制台）让总览表与历史表重取。`.git` 里只认 HEAD、`refs/heads`、`packed-refs`——index、对象、锁是本地重读自己会写的，算进来就会自己触发自己。总览的项目名单击只选中行，双击才打开项目目录（Aurora ≥ 1.38.1 的 `cellStyle=double`）。
- **版面预算优先于说明文字。** 页首不放「这一页是干什么的」。候选项与 `switch` 的 `case` 必须是同一批常量：对不上时不报错，下面永远停在第一支，看起来像没数据。
- **改名的两个名字不能从同一处取。** 「改谁」来自选中行，「改成什么」来自输入框。两边都从输入框取，会把项目改成它自己：指令成功，什么都没发生。面板上不写 `required`：写了会被静默忽略；旧语义还会用一个空框锁死整板按钮。
- **会跑 Git 的取数只针对选中的那一个项目。** 缺项目名就拒绝，不退化为扫全库。排除清单全库共用一份，开页就能看，不碰 Git。`.gitignore` 托管块尾部固定有 `!z-*/` 与 `!z-*/**`，排在全部排除项之后，不进用户清单，也不能关掉——否则 `z-*` 正式快照会被 `*.dll` 之类的排除规则推出索引。
- **不到 100MB 的文件一律不走 LFS。** ≥100MB 的逐个定去向（指针，或不再纳入 git），下次提交生效，历史不改写。不调用 `git lfs track`：它写出的行没有前导斜杠，会匹配任意层级的同名文件。
- **分叉不一律拒绝。** git 判文本冲突，AI 只回答能不能合，Janus 决定怎么合、并执行。有文本冲突、AI 认为两边互相矛盾、AI 不可用，或工作树不干净，就什么都不动。没有文本冲突且 AI 放行：本地提交都还没发布过就变基，否则 merge。一个项目只有自己这一份仓库。
- **新项目预填与首次推送（REQ-019）。** 新建时从模板现有 GitHub 远端取账号，以项目编号预填 HTTPS 地址，只存在该项目本地 Git 配置 `janus.remoteurl`，不注册 origin、不访问 GitHub。GitHub 表格优先显示实际 origin；尚无 origin 时显示预填地址与“待首次推送”，可直接编辑。首次推送先检查该地址：存在则复用，404 才创建（默认公开），其他错误停止；指定账号或组织不能替换为当前登录账号。成功准备后用原输入地址注册 origin。已有 origin 始终直接使用，不被建议地址覆盖。没有预填地址的旧项目沿用按项目编号建仓、优先 SSH 的行为。验收：`RemotePlanContractTests` 与 `GitHubSuite`。
- **已有仓库先指定远端（REQ-018）。** GitHub 子页面直接在原表格的「远端地址」值格编辑，Enter 保存、Escape 取消，不再另设控制面板；保存使用该行取数时固定的项目名，把对应项目的 origin fetch 与 push 同时设为输入地址（无 origin 时添加），保存只改本地配置，不推送、不建 GitHub 仓库；新项目在首次推送前只修改预填地址。`janus.github.status` / `remote` 必须带 `name`，不再依赖当前选择或回退库根；已归档项目先拉取恢复。
- **MCP 只投影只读命令。** 写操作留在页面或确认门后。`janus.status` 是唯一的两段名，`CommandClass=core`，由 `[ModuleCommand]` 投影，不进组合根。指令名与参数键全小写、无连字符；旧名一次切掉，不留别名。
- **产品 Git 不设应用级超时。** 只由 Git/Git LFS 的结果或宿主取消结束。GitHub 诊断和 Smoke 的具名超时是另一条边界，不能跟着删。

## 真机才知道的

- **面板协议是硬依赖。** Aurora 低于 1.9.2 只认 `widgets`，拿到只写 `rows` 的声明会画出一块空面板，而且不报错。低于 1.8.16 时 `channel` / `follows` / `enabledWhen` 被忽略，按钮常亮、跟随框不填，同样不报错。低于 1.8.17 时轮换选项框退成普通选择框，`switch` 变成「该组件待交付」。
- **本机到 GitHub 的单次传输大约超过 300MB 会断**（`early EOF`）。推送因此按预算分批；归档项目的拉取是浅克隆再反复加深。拉取禁止 HTTPS：归档记录里的 https 地址先换成 SSH，换不成就直接失败，不连出去。
- **中文路径会被 git 写成八进制码**，除非按原样打印。别人在 GitHub 上开的分支，刷新要取 origin 全部分支才能画进图谱；没落成本地分支之前，总览不能说已经同步完。
- **status 报 `M` 不等于真有改动。** `eol=crlf` 的文件在索引里记着另一种换行下的尺寸时，git 只看尺寸就判「改过」，`git diff HEAD` 却是空的，`update-index --refresh` 也刷不掉。刷新链路遇到这种「幽灵修改」就对那几个路径 `git add -u`（同一个 blob，暂存区不变）；不处理的话操作列永远是「提交」，点下去又说工作树干净。
- **全库刷新时已归档项目不占并发名额。** 它们本地只剩 z/Z 文件夹，一次 git 都不跑，排在队里只会让要联网的项目白等。
- **刷新 fetch 一律走 SSH。** origin 已是 SSH 就按 origin 取。origin 配成 https 时，只把这一次传输换成 `git@host:path.git`，不改 origin 配置，也不打开 HTTPS。一条 HTTPS 失败会拖住整轮刷新。并发上限 32。
- **生效的是已安装的运行包，不是已提交的源码。** 协议下限改了却没装上去时，页面会变成空面板或占位牌，两边都不报错。

## 工程约定

- 发版改三处版本号：`JanusVersion.props` 的 `HistoryJanusVersion`、`module.manifest.json`、`project.manifest.json`。漏改 `module.manifest` 时宿主静默跳过整个模块。
- 最低宿主 HistoryVulcan 6.0.0。页面要 HistoryAurora ≥ 1.21.1（场景隔离）；面板 `rows` 要 ≥ 1.9.2；带动作选项的差异弹窗要 ≥ 1.24.0；图谱不画左侧泳道标题栏（`laneTitles=false`）要 ≥ 1.33.0，更低的版本照旧画、不报错。GitHub 远端表格行内编辑要 ≥ 1.37.1。分支控制行的选项条要 ≥ 1.38.0，更低的版本整块面板作废、不报到界面上。Aurora 是运行期依赖，不参与编译。
- 生产源码在 `b-Code-Studio`，验证在 `b-Code-Verify`（Contracts、Smoke、ModuleSmoke），不得嵌回生产目录。日常门禁是 `b-Code-Studio/eng/Test-QualityGate.ps1`。
- 模块数据根用宿主给的数据目录，在包槽位之外。`%AppData%\HistoryVulcan\Modules\HistoryJanus` 是只读运行包。
- 候选由 `vulcan.dev.submit` 构建并热装，本仓不自行发布。正式包只有 DLL、XML、manifest 与 checksum。
- 不留 `history/`、方案、需求书。仍有效的结论写进本文、调用处注释或测试。
