# OneHistoryStudio V2.1.3-M2 · Git 管理简约化设计

> 日期：2026-07-17
> 状态：已实现，自动化验收完成，待人工 UI 点验
> 性质：V2.1.3 第二轮简约化收口，作为 V2.1.4 的稳定输入
> 说明：本文件中的 M2 指 V2.1.3 简约化第二轮；原命令集管理页保持不变

## 1. 决策

V2.1.3 第一轮把 `.gitattributes` 做成了通用属性调试器，包含分类预设、文件测试、问题列表、历史分析和多种属性模式。该方案超过个人工作流的实际需求。

新目标只解决一件事：**针对某种文件格式，明确它是否进入 Git，以及进入后是否使用 LFS 或统一 LF。**

每条格式规则只有三个用户可见状态：

| 字段 | 含义 | 写入位置 |
|---|---|---|
| 纳入 Git | 该格式是否默认进入仓库 | 项目根 `.gitignore` |
| 使用 LFS | 进入 Git 后是否保存为 LFS 指针 | 项目根 `.gitattributes` |
| 统一 LF | 进入 Git 后是否按文本处理并统一为 LF | 项目根 `.gitattributes` |

这里的“另一个 `.git` 文件”准确名称是 `.gitignore`。worktree 根下的 `.git` 是 Git 自己维护的仓库指针文件，程序禁止修改。

## 2. 规则语义

### 2.1 四种有效组合

| 纳入 Git | LFS | LF | 结果 |
|---|---|---|---|
| 关闭 | 关闭 | 关闭 | 向 `.gitignore` 写入 pattern；不写属性规则 |
| 开启 | 关闭 | 关闭 | 从托管的 ignore 规则移除 pattern；使用 Git 默认处理 |
| 开启 | 开启 | 关闭 | 写入标准 LFS 规则 |
| 开启 | 关闭 | 开启 | 写入 `text eol=lf` |

禁止以下无意义或冲突组合：

- “不纳入 Git”时，LFS 和 LF 自动关闭；
- LFS 与 LF 互斥；开启一个时自动关闭另一个；
- 不允许用户自由输入 `filter/diff/merge/eol` 属性组合。

标准输出固定为：

```gitattributes
*.xlsx filter=lfs diff=lfs merge=lfs -text
*.cs text eol=lf
```

### 2.2 `.gitignore` 与索引

`.gitignore` 只影响尚未跟踪的文件。已经进入索引的文件不会因为新增 ignore 规则自动退出仓库。

因此保存规则前必须显示受影响文件数量，确认后执行：

- 关闭“纳入 Git”：向 `.gitignore` 写规则，并对当前已跟踪的精确文件执行 `git rm --cached`，只从索引移除，不删除本地文件；
- 开启“纳入 Git”：移除托管的 ignore 规则，并把当前匹配文件加入索引；
- 修改 LFS/LF：对当前匹配且已跟踪的文件重新 `git add`，让 clean filter 或换行规则进入索引；
- 所有路径先由 Git 列出为精确相对路径，再逐项经结构化 `GitRunner` 传递，禁止把用户 pattern 直接拼进 shell。

这些操作只更新规则文件和暂存区，不自动 commit、push 或重写历史。

## 3. 页面整合

不再保留独立“Git 属性”工具窗口。Git 格式规则完全集成到现有“项目总览/项目操作”页面，旧窗口 ID `attributes` 在实现时删除。

选择一个 Project 后，在同一页面显示一个紧凑的“Git 文件规则”区域：

```text
Pattern          纳入 Git   LFS   LF    当前状态                 文件数
*.xlsx              是       是    否    8/8 已是 LFS 指针          8
*.cs                是       否    是    LF 规则生效                42
*.tmp               否       否    否    3 个文件已忽略              3
```

区域只提供：

- Pattern 输入框和“添加”；
- 三个开关；
- 删除当前规则；
- 保存当前修改；
- 重新读取。

保存前使用普通确认框列出：

- `.gitignore` 将增加/删除哪些 pattern；
- `.gitattributes` 将增加/删除哪些标准行；
- 将加入、移出或重新写入索引的文件数量；
- 本次不会 commit、push 或迁移历史。

不再提供独立 diff 页、文件测试页、问题页、扫描与历史页。

## 4. 文件所有权

程序只管理项目根的两个文件：

```text
<Project>/.gitignore
<Project>/.gitattributes
```

使用明确注释块标记程序所有内容：

```text
# OneHistoryStudio managed begin
*.xlsx
# OneHistoryStudio managed end
```

```gitattributes
# OneHistoryStudio managed begin
*.xlsx filter=lfs diff=lfs merge=lfs -text
# OneHistoryStudio managed end
```

约束：

- 注释块外的人工规则原样保留；
- 首次读取可识别现有标准 LFS/LF 行，但不自动改写；
- 用户确认保存后，选中的既有标准行迁入托管块并去重；
- 非标准属性行只显示“人工规则未托管”数量，不提供通用编辑器；
- 不扫描或编辑嵌套目录中的 `.gitignore/.gitattributes`。

## 5. 指令设计

页面仍然只调用指令总线，不直接访问文件、Git 或数据库。

保留最小指令集：

| 指令 | 行为 | 风险 |
|---|---|---|
| `git.rule.list name=` | 列出托管格式规则、实际索引状态和文件数 | 只读 |
| `git.rule.set name= pattern= track= lfs= lf= apply=false` | `apply=false` 返回预览；`true` 经本地确认后写规则并同步索引 | 本地确认 |
| `git.rule.remove name= pattern= apply=false` | 预览或删除托管规则；不删除本地文件 | 本地确认 |

不新增第二套服务 API。三条指令继续经过 `CommandParser → CommandBus → GitFileRuleService → GitRunner`。

自动加载和刷新同样执行这些指令，并按现有规则完整回显、写日志、触发 `Executed`。不增加 Quiet 模式，不允许页面旁路总线，也不为 UI 查询制造特殊生命周期。
