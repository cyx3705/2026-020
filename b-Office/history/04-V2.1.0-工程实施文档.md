## 0. 一句话定义

V2.1.0 把**指令总线本身**封装为 MCP 服务：外部 AI 客户端经 MCP 协议看到的每一个工具，
就是程序里的一条指令（内置 + proj.* + 模块 DLL 指令一视同仁）；
MCP 网关与模块 DLL **彻底解耦**——它只认识指令注册表，不认识任何 DLL。

## 1. 架构判定：为什么封装指令、不封装 DLL

### 1.1 两种模型对比

| | MyAPI-Lite 旧模型（否决） | V2.1 指令封装模型（采纳） |
|---|---|---|
| 暴露对象 | DLL 里的公共方法 → HTTP 端点/MCP 工具 | **指令注册表里的指令** → MCP 工具 |
| 覆盖范围 | 只有模块 DLL 的能力 | 内置(app/win/db/res/panel/layout) + proj.* + module.* + 全部模块指令 |
| 安全闸口 | 无（方法直调） | 复用总线：参数校验、ConfirmPrompt、受保护分支、留痕 |
| 与宿主耦合 | MCP 层要理解反射/ALC/XML 注释 | MCP 层只依赖 CommandRegistry / CommandBus 两个公开类型 |
| 热重载联动 | 需另行同步端点表 | 模块上/下线即指令注册/注销，工具列表**天然同步** |
| MyAPI-Lite 本体 | 被硬塞进宿主 | 保持冻结退役，只留概念遗产 |

### 1.2 分层图（V2.1 全景）

```
┌─────────────────────────────────────────────────────────────┐
│ 外部 AI 客户端(Claude Code / aimcp / 任意 MCP client)          │
└──────────────────────────┬──────────────────────────────────┘
                           │ MCP(JSON-RPC 2.0 / Streamable HTTP,仅 localhost)
┌──────────────────────────▼──────────────────────────────────┐
│ McpGateway(V2.1 新增,App 层)                                 │
│   tools/list ← CommandSchemaExporter(指令元数据 → JSON Schema)│
│   tools/call → CommandBus.ExecuteAsync(text, "MCP:客户端")    │
│   策略闸口:暴露分级 / token / 留痕 / 超时                      │
├─────────────────────────────────────────────────────────────┤
│ 指令总线 CommandBus + CommandRegistry(框架,0.4.2,不改)        │
│   ▲内置指令组   ▲proj.*   ▲module.*   ▲模块 DLL 动态指令       │
├───────────────┬─────────────────────────────────────────────┤
│ App 业务层     │ ModuleHost(V2-M3 已有):Modules\*.dll         │
│ proj/留痕/... │   → 鸭子契约识别 → 注册为指令(热重载/注销)      │
└───────────────┴─────────────────────────────────────────────┘
```

### 1.3 三条设计铁律（本版新增，与模板三不变量并列）

1. **MCP 网关唯一上游是指令总线**：网关代码禁止 import ModuleHost、禁止反射模块类型、
   禁止绕过总线直调任何服务——将来换掉模块机制，MCP 层零改动。
2. **一切经过总线的调用必留痕**：MCP 来源的执行以 `MCP:<客户端名>` 作为 source 标签，
   控制台可见回显，与 UI / 手动 / 脚本同权同轨。
3. **默认不暴露、暴露必分级**：服务默认关闭；开启后按策略分级过滤指令；
   带 ConfirmPrompt 的危险指令 V2.1.0 一律对 MCP 拒绝（见 §6 与开放问题 Q211-1）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| MCP | Model Context Protocol；本版实现 Streamable HTTP 传输上的 JSON-RPC 2.0 服务端 |
| 工具（tool） | MCP 客户端可调用的能力单元；本版 1 工具 = 1 指令 |
| 工具名 | 指令名的 MCP 合法化形式：`proj.list` → `proj_list`（`[a-zA-Z0-9_-]`，点替换为下划线） |
| 网关 / McpGateway | App 层新增的 MCP 服务端组件（HttpListener，仅绑定 127.0.0.1） |
| 暴露策略 | readonly / standard 两档（V2.1.0），决定哪些指令成为工具，见 §6.2 |
| 元数据导出 | CommandDescriptor(Name/Summary/Parameters/Example) → MCP tool JSON Schema 的映射 |

## 3. 功能需求 A —— 指令元数据自描述层（`CommandSchemaExporter`）

> 先做纯内存映射层并给本地指令验收入口，**不开网络即可验收**，这是 M1 与 M2 解耦的关键。

| 编号 | 需求描述 | 优先级 |
|---|---|---|
| MC-01 | 遍历 CommandRegistry.All()，把每条指令导出为 MCP tool 描述：name(合法化)、description(=Summary，追加 Example)、inputSchema(JSON Schema object) | P0 |
| MC-02 | ParameterSpec → JSON Schema 属性映射：String→string、Int→integer、Double→number、Bool→boolean；Required→required 数组；Default→default；Description→description；AllowedValues→enum | P0 |
| MC-03 | 工具名合法化与唯一化：非法字符替换 `_`；冲突时追加序号（沿用 MyAPI-Lite MakeToolName 思路，仅思路） | P0 |
| MC-04 | 导出结果**每次调用现算**（不做缓存）：模块热重载后 tools/list 即刻反映指令增删 | P0 |
| MC-05 | 新指令 `mcp.schema [name=]`：不带参输出全部工具的 JSON 清单（回显 + Data）；带 name 输出单条完整 JSON Schema——本地验收与调试入口 | P0 |
| MC-06 | 反向解析：tools/call 的 arguments(JSON) → 指令文本 `域.动作 键="值"`；字符串值一律加引号并转义内部引号；bool/number 按不变文化格式化 | P0 |

## 4. 功能需求 B —— MCP 网关服务（`McpGateway`）

| 编号 | 需求描述 | 优先级 |
|---|---|---|
| MG-01 | 传输：HttpListener 监听 `http://127.0.0.1:<port>/mcp`（默认端口 8737，配置键 `mcp.port`）；仅回环地址，拒绝其他绑定 | P0 |
| MG-02 | 协议：JSON-RPC 2.0 单请求/单响应（Streamable HTTP 的无状态子集）：`initialize`、`notifications/initialized`、`ping`、`tools/list`、`tools/call`；其余方法返回 method not found | P0 |
| MG-03 | `tools/call` 流程：解析工具名 → 查注册表 → 策略过滤(§6) → 组装指令文本 → `CommandBus.ExecuteAsync(text, "MCP:<clientInfo.name>")` → 结果映射 | P0 |
| MG-04 | 结果映射：CommandResult.Message → content[0].text；执行失败 → isError=true + 错误文本；Data 非空时序列化为 JSON 追加为第二段 text（结构化数据通道） | P0 |
| MG-05 | 生命周期指令域 `mcp.*`：`mcp.start [port=]` / `mcp.stop` / `mcp.status`（运行状态、端口、策略、已暴露工具数、累计调用数）；配置键 `mcp.autostart`（默认 false，app.set 可改） | P0 |
| MG-06 | 线程模型：HttpListener 回调在线程池 → ExecuteAsync 派发遵循总线既有约定（RequiresUiThread 指令由总线/网关经 Dispatcher 序列化到 UI 线程），全程不阻塞 UI | P0 |
| MG-07 | 超时：单次 tools/call 执行超时可配（`mcp.timeout`，默认 120s）；超时返回 isError，指令继续在宿主内跑完并留痕（不撕裂总线执行） | P1 |
| MG-08 | 进度：ctx.Progress 上报在 V2.1.0 仅落控制台（既有行为）；MCP progress notifications 列为 P2 预留 | P2 |
| MG-09 | 服务开关状态与端口在状态栏或占位页可见（轻量提示即可，不新造窗口） | P1 |

## 6. 功能需求 D —— 安全策略

### 6.1 基线

| 编号 | 需求描述 | 优先级 |
|---|---|---|
| MS-01 | 服务默认关闭；仅 `mcp.start` 或 `mcp.autostart=true` 开启 | P0 |
| MS-02 | 仅监听 127.0.0.1；可选共享密钥 `mcp.token`（非空时请求头 `Authorization: Bearer <token>` 必须匹配，否则 401） | P0 |
| MS-03 | 硬排除清单（任何策略下都不暴露）：`app.exit`、`debug.*`、`mcp.*`（防远端自锁/自杀/递归）；清单为代码内常量 + 注释说明 | P0 |
| MS-04 | **带 ConfirmPrompt 的指令（proj.delete / commitall / pushall / repair / db 危险写）V2.1.0 对 MCP 一律拒绝**，返回明确文案「危险指令须在宿主 UI/控制台人工执行」——总线确认闸口是模态 UI，远端没有"人"来点确认，自动放行等于拆闸（Q211-1 记录 full 档位的将来方案） | P0 |
| MS-05 | 每次拒绝（策略/排除/危险/token 失败）都写 mcp_history(result=拒绝) 并告警日志 | P0 |

### 6.2 暴露分级（配置键 `mcp.policy`，默认 `readonly`）

| 档位 | 暴露范围 | 典型可用 |
|---|---|---|
| `readonly` | 白名单式只读指令：help、proj.list/tree/scan/config/metalist、db.query/tables/schema、module.list、win.list、layout.list、app.get、history | AI 查询项目库、读表、看模块 |
| `standard` | readonly + 非确认类动作指令：proj.create/commit/push/open/note/metaopen、db.insert/update(无确认路径)、panel.set、win.show/dock、log.level、模块 DLL 全部指令 | AI 建项目、提交、驱动模块能力 |

> 分级判定实现：readonly 白名单为代码内清单；standard = 全量 −（硬排除 ∪ ConfirmPrompt 类）。
> 模块 DLL 指令归入 standard 档（模块作者的方法本身无确认语义；需要只读暴露的模块列 Q211-2）。

## 8. 非目标（V2.1.0 明确不做）

- 不监听非回环地址、不做 HTTPS、不做多用户/OAuth（个人工具，token 足够）。
- 不做 MCP resources / prompts / sampling，只做 tools。
- 不做 SSE 长连接与服务器推送通知（listChanged 由客户端重新 tools/list 覆盖）。
- 不修改 AppShell.Core / Services / Shell 三目录（初步核对：CommandRegistry.All /
  CommandDescriptor 各字段 / CommandBus.ExecuteAsync 均为公开成员，**预计零框架改动**；
  若实施中发现确需扩展点，按演进手册上报并走 0.4.3 回灌流程，禁止私改）。
- 不复活 MyAPI-Lite 进程、不引用其程序集；其 Mcp.cs 只作协议实现的参考读物。

## 10. 实现边界（给开发者 / AI）

1. **新增文件全部在 App 层**：`src\App\Mcp\CommandSchemaExporter.cs`、`McpGateway.cs`、
   `McpCommands.cs`（mcp.* 域）、`McpHistoryRecorder`（可并入既有 HistoryRecorder）。
2. **配置键**：`mcp.port / mcp.policy / mcp.token / mcp.autostart / mcp.timeout`，
   全部走 SettingsService（app.set 即改，PJ-12 同律）。
3. **装配点**：App.xaml.cs 创建 McpGateway(依赖 window.Commands + exporter + recorder)，
   ConfigureCommands 注册 mcp.* 域；OnExit Dispose（停监听）。
4. **JSON-RPC 手写即可**：System.Text.Json + HttpListener，单文件百行级；不引 ASP.NET Core、
   不加 NuGet 包（NuGet 仅 nuget.org 且尽量零新增依赖）。
5. **验收脚本化**：M2 全部验收项用 `Invoke-RestMethod -Method Post -Body(JSON-RPC)` 打，
   配合既有 `--exec` / `--yes` 自动化惯例；沙盒仓库纪律不变（危险验收先沙盒）。
6. **部署纪律**（V2.0 经验固化）：验收用部署区 exe（`C:\OneHistory\OneHistory-Push\OneHistoryStudio\`），
   不用 worktree 内产物；从资源管理器启动，**严禁从带文件沙盒的 agent 终端启动**（见 V2.0 排障记录）。

## 13. 远期规划（V2.2 方向：项目库自扩展飞轮）

> 2026-07-15 与用户讨论定向：项目库中的项目编译出的 DLL 工具回流为本程序的模块，
> 形成「管理程序管理项目 → 项目产出工具 → 工具武装管理程序」的闭环。
> 判定：**不用裸复制**（版本漂移 / 依赖打架 / 无溯源 / 安全面失控），
> 采用「清单声明 + 程序主导同步」：

| 要点 | 方案 |
|---|---|
| 声明 | 项目在自己 worktree 的 z 级元文件夹放 `module.manifest.json`（模块名/版本/产物相对路径），复用 V2.0.1 Meta 约定作为发现挂点 |
| 指令 | `tool.scan`：沿 worktree 清单发现全部 manifest，标注部署副本是否过期；`tool.sync [name=]`：复制 DLL+依赖入 Modules，写溯源（来源分支/哈希/时间），热重载自动接手 |
| 隔离 | ModuleHost 演进为「Modules 下每子目录一个模块 + 独立 ALC」，解决多模块依赖版本冲突 |
| 边界 | 同步是显式指令（人在环上，可被面板/MCP standard 档触发），不做全库自动装载；工具只进数据目录 Modules，Push 部署区保持纯宿主不可变 |
| 链路 | 项目 DLL → tool.sync → 指令域（V2-M3）→ MCP 工具（V2.1）——三跳全自动 |
