# V3.2.0 项目总览与 Meta 合并

> 状态：开发候选完成；不正式发布、不部署

## 目标

HistoryJanus 3.2.0 把 Meta 文件夹浏览合并进项目总览，模块只注册 `overview`、`projops`、`history` 三个页面；删除独立 Meta 页面和继承树页面，分支历史的查询、详情、差异、回滚、重置和强推能力全部保留。

## 实现

- 项目总览由两列调整为“编号、分支 / 项目、元文件夹”三列，保留搜索、刷新、共享项目选择和双击打开项目。
- 刷新时并行调用 `proj.list` 与 `proj.metalist`，按项目名（忽略大小写）合并；Meta 加载失败时仍显示项目列表，状态栏报告降级状态。
- 元文件夹列显示第一个可点击文件夹名；多个时追加 `+N`，点击弹出完整列表。点击执行现有 `proj.metaopen`，不改变项目选择。无 Meta 的项目显示 `-`，组内按不区分大小写的名称排序。
- 搜索同时匹配项目名、Meta 名和 Meta 路径；合并、匹配与打开命令投影收敛为 `OverviewMetaMerge` 纯函数，便于无 WPF 的冒烟验证。
- 删除 `MetaView`、`BranchTreeView`、`BranchTreeItem` 及稳定窗口 ID `meta`、`tree`；保留 `proj.metalist`、`proj.metaopen`、`proj.tree`、Meta 服务与 `BranchTreeService`/`BranchTreeNode`，分支历史继续依赖继承关系计算。
- `overview` 默认左侧 `0.20`，`projops` 右侧 `0.28`，`history` 中央 `0.55`；不修改 HistoryVulcan。
- 版本源、manifest、状态命令、模块 API 与现行文档更新为 `3.2.0`；命令名称、参数、结果结构和数据目录均不改变。
