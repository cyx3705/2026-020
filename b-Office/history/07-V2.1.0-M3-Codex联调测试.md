## 4. A213-2 模块能力直达

### 4.1 它实际要验证什么

这不是测试加法本身，而是验证完整的两跳动态能力链：

```text
DemoModule.dll
  → ModuleHost 识别模块契约
  → 注册 DemoModule.Add 指令
  → MCP tools/list 动态导出 DemoModule_Add
  → Codex 原生调用
  → CommandBus 参数绑定 a=1、b=2
  → 模块方法返回 3
```

任何一环有问题，Codex 都看不到工具或得不到结果。

### 4.2 执行前准备

1. 确认从资源管理器启动的是包含 M2 网关的最新部署版，不是 M1 旧部署版。
2. 构建 `samples\DemoModule`。
3. 将 `DemoModule.dll`、`DemoModule.xml` 及模块所需契约程序集放入：

```text
C:\Users\Administrator\AppData\Roaming\OneHistoryStudio\Modules
```

4. 在 OneHistoryStudio 控制台确认：

```text
module.list
app.set key=mcp.policy value=standard
mcp.status
```

通过标准：`module.list` 显示 DemoModule，`mcp.status` 显示 standard，工具数应多于 readonly
状态的 15 个。

### 4.3 Codex 测试指令

模块投放后新建 Codex 任务，确保客户端重新获取 tools/list，然后输入：

```text
使用 onehistory 的 DemoModule_Add，令 a=1、b=2
```

通过标准：Codex 原生工具调用返回 `3`；OneHistoryStudio 控制台出现对应 MCP 来源回显；
`mcp_history` 新增成功记录。

## 5. A213-3 在线热重载

### 5.1 它实际要验证什么

验证 MCP 工具清单不是启动时固定快照，而是跟随模块注册表变化：

```text
服务不停机
→ 投放/移除模块 DLL
→ ModuleHost 注册/注销命令
→ CommandSchemaExporter 重新现算工具
→ 客户端刷新后工具相应出现/消失
```

### 5.2 建议步骤

1. 保持 OneHistoryStudio 与 MCP 服务运行。
2. 记录当前 `module.list` 和工具数。
3. 移除或改名 DemoModule DLL，确认宿主日志显示模块下线。
4. 调用 `module.list`，确认 DemoModule 消失。
5. 新建 Codex 任务或以客户端支持的方式刷新 MCP 元数据，确认 `DemoModule_Add` 不再存在。
6. 把 DLL 放回，确认模块重新加载。
7. 再刷新 Codex 工具列表，确认 `DemoModule_Add` 恢复并再次调用得到 `3`。

注意：服务端 tools/list 每次现算，但 Codex 单个任务可能持有任务启动时的工具快照。新建任务后
工具变化可见，仍然能证明服务端热重载成立；应把“服务端即时变化”和“客户端何时刷新”分别记录。

## 6. fable5 任务的直白翻译

fable5 交付的任务可以拆成以下四句话：

1. **不要再用 PowerShell 假装客户端**：必须让一个真实 AI 客户端通过 MCP 调用。
2. **先证明宿主自己的命令能用**：`proj_list` / `proj_tree` 代表 OneHistoryStudio 内置业务能力。
3. **再证明 DLL 能穿透到 AI**：`DemoModule_Add` 代表运行时加载的第三方模块能力，不是写死的网关接口。
4. **最后证明不用重启**：模块投放、下线、恢复时，AI 可见工具随注册表同步变化。

Claude Code 只是原计划选定的客户端。换成 Codex 后，验收目标没有降低，反而已经证明本项目能被
OpenAI 的真实客户端原生发现和调用。

## 8. 安全边界

- 联调阶段 token 未设置仅适用于 `127.0.0.1` 本机回环，不得直接开放公网。
- standard 会开放非确认类写操作；测试指令必须明确指定，不做探索性批量写入。
- 带 `ConfirmPrompt` 的危险指令仍应由 MCP 网关拒绝，不因 standard 放行。
- 热重载测试只操作 `%AppData%\OneHistoryStudio\Modules` 中的测试模块，不动生产项目源码。
