# OneHistoryStudio 2.1.0-M1.5 工程修复快照

> 日期：2026-07-15  
> 性质：V21-M1 与 V21-M2 之间的工程质量修复  
> 边界：只修改 App 自由区与项目文档，不修改 MCP 网关协议和 AppShell 三个基线项目

## 1. 修复目标

本快照不增加 MCP 功能，集中消除 M2 开始接收外部参数前已经识别出的 Git 参数与文件系统边界
风险。版本显示暂定为 `2.1.0-M1.5`，M2 可在此基础上继续开发。

## 2. 已完成

### 2.1 GitRunner 结构化参数

- `GitRunner.RunAsync` 从单个命令字符串改为独立参数列表。
- 内部使用 `ProcessStartInfo.ArgumentList`，不再由调用方拼接引号。
- ProjectService 与 WorktreeLfsHelper 的全部 Git 调用已迁移。
- commit message、中文路径、空格、引号和尾部反斜杠作为单个参数原样传给 Git。
- 超时和错误消息只做参数格式化显示，不把显示文本重新用于执行。

### 2.2 `proj.repair` 零删除边界

- 删除前同时读取 worktree 清单与分支清单，生成完整修复计划。
- 现有 worktree 和重建目标必须是 `proj.worktreeroot` 的直接子目录。
- 裸仓库、根目录外路径、嵌套目标、符号链接和目录联接一律拒绝。
- 任意一个计划项不合规时，整次 repair 在删除任何目录前失败。

### 2.3 Meta 路径边界

- `proj.metaopen` 不再只检查目录名是否以 `z/Z` 开头。
- 目标必须存在、不是 reparse point，且父目录必须匹配 Git 已登记的 worktree。
- `path=` 与 `name=+meta=` 两条入口共用相同验证。

### 2.4 源码基础忽略

- 新增项目级 `.gitignore`，覆盖 `.vs`、`bin/obj`、测试输出和 VS 用户状态。
- 不自动取消跟踪历史产物，避免在 M2 开发期间制造大规模索引变化。
- `Publish/` 暂不忽略，等待 Ignore 控制界面的制品策略定稿。

### 2.5 Schema 规格一致性

- A211-2 明确：`proj.create.base` 的缺省值来自运行时 `proj.basebranch`。
- 静态 Schema 不输出可能过期的 default，仅由 description 声明动态缺省行为。
- 此项是规格措辞修订，不改变 MCP M1 实现。

## 3. 明确未做

- 不修改 `src/App/Mcp`，不实现或调整 M2 网关。
- 不新增 `.gitignore` 控制窗口和 `proj.ignore.*`；保留在后续治理里程碑。
- 不新增 `project.location.*`，位置迁移与外部 worktree 登记策略后续单独实施。
- 不执行 `git rm --cached`，不清理当前已经跟踪的 `.vs/bin/obj/Publish`。
- 自动化测试不作为本快照阻塞项。

## 4. M2 接续约束

- MCP 传入的所有 Git 参数继续走结构化 GitRunner，网关不得恢复字符串命令拼接。
- MCP 对 `proj.repair` 的危险拒绝策略保持不变；路径守卫属于业务层最后防线，不能由策略绕过。
- 后续新增会打开、删除或创建目录的命令必须复用同等级路径验证。
- M2 合并时可以把显示版本从 `2.1.0-M1.5` 推进为对应里程碑号，本文档保留为修复记录。
