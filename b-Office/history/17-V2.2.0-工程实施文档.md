## 0. 一句话定义

打通「**管理程序管理项目 → 项目产出工具 DLL → 工具回流武装管理程序 → Codex 经 MCP 调用工具**」
的完整飞轮：项目库中任何项目按约定声明自己的工具产物，一条 `tool.sync` 完成入库，
自动成为指令域与 MCP 工具；配套解锁危险指令的「宿主确认中继」，让 Codex 能发起、
人类在宿主端把关。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 工具项目 | 项目库中产出可装载 DLL 的项目（worktree） |
| 清单 / manifest | 工具项目 z 级元文件夹中的 `module.manifest.json`，声明工具产物 |
| 同步 / sync | 把清单声明的产物复制进宿主 Modules 目录并落溯源的动作（显式指令，人在环上） |
| 溯源 | tool_registry 表记录:模块 ← 来源分支/产物哈希/同步时间/版本 |
| 模块槽 | `Modules\<模块名>\` 子目录:一个模块及其依赖的独立装载单元(独立 ALC) |
| 确认中继 | MCP 调用危险指令时,宿主弹确认框由人裁决,远端等待结果的机制(Q211-1) |

## 3. 功能需求 A —— 清单与发现（`tool.scan`）

| 编号 | 需求描述 | 优先级 |
|---|---|---|
| TL-01 | 清单约定：工具项目在其 **z 级元文件夹**放 `module.manifest.json`。字段：`name`（模块名=指令域名，必填）、`version`、`description`、`artifact`（DLL 相对 worktree 的路径，必填）、`docs`（XML 注释文件相对路径，可选，缺省取 artifact 同名 .xml）、`panel`（面板 JSON 相对路径，可选）、`deps`（依赖 DLL 相对路径数组，可选）、`mcpExposure`（standard/readonly/hidden，可选，默认 standard，见 §6） | P0 |
| TL-02 | `tool.scan`：沿 proj.list 的 worktree 清单枚举全部 manifest；输出每项：模块名/版本/来源项目/产物是否存在/**部署状态**（未同步·最新·已过期——按产物文件 SHA-256 与 tool_registry 对比）；Data 携带结构化清单（MCP 可读） | P0 |
| TL-03 | 清单校验：name 非法（与内置域冲突/含非法字符/重复）、artifact 缺失、路径越出所属 worktree（复用 M1.5 同级路径守卫）逐项标注错误，不中断扫描 | P0 |
| TL-04 | `tool.scan` 属只读，进 readonly 暴露档——Codex 在只读档即可盘点全库工具资产 | P0 |

## 4. 功能需求 B —— 同步与溯源（`tool.sync` / `tool.remove`）

| 编号 | 需求描述 | 优先级 |
|---|---|---|
| TS-01 | `tool.sync name=<模块名>`：按清单把 artifact+docs+panel+deps 复制入**模块槽** `Modules\<name>\`；写 tool_registry（模块名/来源分支/版本/产物 SHA-256/同步时间）；热重载自动接手。`tool.sync all=true` 同步全部已声明且非最新的工具 | P0 |
| TS-02 | `tool.remove name=<模块名>`：删除模块槽 + 注销溯源记录（面板副本随 MD-08 机制回收）；带 ConfirmPrompt（走总线确认闸口） | P0 |
| TS-03 | 溯源表 `tool_registry`（main 库,表窗口可查）：name/branch/version/sha256/synced_at/source_path；`tool.list`：已同步工具及溯源，并标注当前装载状态（与 module.list 互补：一个看"来源"，一个看"运行时"） | P0 |
| TS-04 | 同步为**显式动作**：不做全库自动装载、不做文件监听自动 sync；可被 UI 按钮/面板/MCP standard 档触发（sync 无确认语义,remove 有） | P0 |
| TS-05 | 安全底线：目标模块槽只能位于 Modules 目录内；同步前后校验 SHA-256 一致；工具 DLL 永不进 Push 部署区（部署区 = 纯宿主不可变） | P0 |
| TS-06 | 「模块管理」页升级：合并展示 tool.scan 结果（可同步/已过期高亮），行内按钮触发 tool.sync / tool.remove（按钮=组装指令经总线，不变量 1） | P1 |

## 5. 功能需求 C —— 模块槽隔离（ModuleHost 演进，App 层）

| 编号 | 需求描述 | 优先级 |
|---|---|---|
| MH-01 | Modules 目录布局升级：根目录平铺 DLL（既有行为）**继续支持**；新增每模块槽 `Modules\<name>\` 子目录——槽内 DLL+依赖装入**该槽独立的可回收 ALC**，槽间依赖版本互不冲突 | P0 |
| MH-02 | 槽的模块识别沿用鸭子契约；槽内非契约 DLL 一律视为该槽私有依赖，不再落入共享解析路径 | P0 |
| MH-03 | 热重载粒度保持整体重建（与既有一致,不追求单槽增量）；防抖/监听扩展到子目录（IncludeSubdirectories） | P0 |
| MH-04 | `<name>.panel.json` 在槽内同样被 MD-08 同步机制发现（ModulePanelSync 扫描一层子目录） | P1 |
| MH-05 | module.list 增列来源槽（根平铺 / 槽名），与 tool.list 的溯源信息对得上 | P1 |

> 边界：ModuleHost/ModulePanelSync 均在 App 自由区，本域**零框架改动**。

## 7. 非目标（V2.2.0 明确不做）

- 不做全库自动装载/自动 sync（人在环是底线）。
- 不做 SSE / listChanged 推送（CX-04 对策覆盖）。
- 不做动态停靠窗口（Q211-4 继续挂账——需动 DockingHost 冻结区,如实施须走 0.4.4 上报回灌,
  与本版主题无关,不搭车）。
- 不拆 ProjectService / GitFileRuleService 大文件（质量项另行小版本）。
- 不做工具项目的自动构建（manifest 指向**已构建**产物;构建何时跑由项目自己负责）。
- 不改 GitRunner/路径守卫/提示词治理审批链内部行为（M1.5 与 V2.1.2 纪律延续）。

## 9. 实现边界（给开发者 / AI）

1. **新增文件**：`Git\ToolManifest.cs`（清单模型+校验）、`Git\ToolSyncService.cs`（扫描/同步/溯源）、
   `Git\ToolCommands.cs`（tool.* 域,source="tool"）;溯源表建表并入 HistoryRecorder 同律
   （SqlText 取用）;确认中继改动集中 `Mcp\McpGateway.cs` + `McpExposurePolicy.cs`。
2. **manifest 发现**复用 Meta 扫描的 z 级目录枚举路径,路径校验复用 M1.5 守卫等级;
   文件哈希用 SHA-256（与 command.manual 的哈希习惯一致）。
3. **ModuleHost 改造自查清单**：槽 ALC 的 Load 回调解析顺序=槽内→null 回落框架;
   卸载时逐槽 Unload;监听 IncludeSubdirectories=true 后注意防抖对深层批量拷贝的覆盖。
4. **确认中继线程模型**：网关线程 → Dispatcher.Invoke 弹框（复用 Confirmation 通道）,
   等待用 TaskCompletionSource+超时;宿主同一时刻多个中继请求按序弹框,不并发弹窗。
5. **配置键**：`mcp.confirm`（deny/host）、`mcp.confirmtimeout`（秒,默认 60,夹取 10~600）。
6. **验收纪律**：部署区 exe+资源管理器启动;Codex 验收前重启任务取新工具快照;
   独立端口测试先 mcp.stop 再 mcp.start port=,测毕恢复 8737(V2.1.6 运维备注);
   动第一行代码前采 v217 快照基线（docs\snapshots\v217\,沿用 V2.1.6 采集脚手架）。
7. **每里程碑独立提交**,沙盒先行,main.db 迁移动作(建 tool_registry)走 StartupMigrations v3。
