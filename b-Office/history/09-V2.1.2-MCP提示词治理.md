# OneHistoryStudio V2.1.2 · MCP 提示词治理与勘误历史

> 日期：2026-07-16  
> 性质：V2.1.1 提示词覆盖机制的安全升级  
> 状态：已实现并部署，页面视觉留人工点验
> 前置版本：V2.1.1（`mcp.desc` 覆盖式存储 + MCP 工具管理页）

## 1. 版本目标

V2.1.2 允许 AI 发现并提交 MCP 工具描述的修改建议，同时保留人类最终决定权。系统必须能回答：

- 当前提示词来自哪个修订；
- 谁在何时、因为什么提出修改；
- 修改前后差异是什么；
- 哪条勘误或事故记录支持这次修改；
- 谁批准、拒绝、应用或回滚了修改。

本版采用 **AI 提议、人类审核、修订生效、全程可回滚** 的模型，不向远程 MCP 客户端开放直接覆盖能力。

同时把 V2.1.1 暴露出的应用名/版本号硬编码问题列为本版 **P0 前置治理**：先建立应用身份单一真值，再继续扩展 MCP，避免每次发布分别修改窗口、程序集和协议响应。

## 2. 当前问题

V2.1.1 的 `mcp_descriptions` 只有 `command / description / updated`，保存使用覆盖语义，适合本地人工小改，但不适合 AI 自助治理：

1. 旧值被覆盖，缺少完整修订链；
2. 没有来源客户端、修改理由、证据和审核人；
3. 工具描述、勘误知识、失败事件混在同一段文本会持续膨胀；
4. AI 直接修改决定自身工具选择的描述，存在自我授权、提示词漂移和全局污染风险；
5. 客户端可能缓存 `tools/list`，服务端生效不等于当前 AI 会话立即刷新。

## 3. 概念边界

| 对象 | 作用 | 是否进入 `tools/list.description` |
|---|---|---|
| 工具描述 | 简明说明用途、边界、副作用和关键参数 | 审核应用后进入 |
| 修改提案 | 新描述、理由、证据及差异 | 否 |
| 勘误 | 指出错误说法及正确解释 | 否，可作为提案证据 |
| 事故记录 | 保存预期、实际、症状和处理结果 | 否，可作为提案证据 |
| MCP Prompt | 可复用的多工具工作流模板 | 否，属于 MCP `prompts` 能力 |

本版治理的是 **工具元数据**。MCP 协议的 `prompts/list`、`prompts/get` 不与工具描述编辑混为一谈，协议级 Prompts/Resources 另列后续能力。

## 4. P0：应用身份单一真值

### 4.1 已确认的问题

V2.1.1 源码和交付物存在三套不一致信息：

- `App.xaml.cs` 的 Shell 显示版本是 `2.1.1`；
- `McpGateway.cs` 的 `serverInfo.version` 仍硬编码为 `2.1.0`；
- EXE 的 `FileVersion/ProductVersion` 仍以 SDK 默认 `1.0.0` 为核心版本。

程序名同样散落在 `AppPaths`、异常对话框、启动日志、Shell配置和 MCP `serverInfo.name` 中。任何一个调用点漏改，都会形成“程序已经升级但某个出口仍报告旧身份”的收口漏洞。

### 4.2 身份字段定义

| 字段 | V2.1.2 值 | 用途 |
|---|---|---|
| Name | `OneHistoryStudio` | 程序显示、机器标识、程序集、数据目录、日志、MCP server name |
| SemanticVersion | `2.1.2` | Shell、MCP、日志、关于页和文档 |
| FileVersion | `2.1.2.0` | Windows EXE/DLL 文件属性 |
| InformationalVersion | `2.1.2` 或 `2.1.2+<commit>` | 产品版本与构建追踪；核心版本必须是 2.1.2 |

名称不再区分 ProductName 与 DisplayName。所有机器和用户可见出口统一使用 `OneHistoryStudio`，不得由页面、Shell或协议层自行改写。该名称同时是数据目录兼容标识，后续改名必须作为带数据迁移的独立破坏性版本处理。

### 4.3 单一来源方案

构建身份只在 `src/App/App.csproj`（或仓库统一 `Directory.Build.props`）声明一次：

```xml
<Product>OneHistoryStudio</Product>
<Title>OneHistoryStudio</Title>
<Version>2.1.2</Version>
<AssemblyVersion>2.1.2.0</AssemblyVersion>
<FileVersion>2.1.2.0</FileVersion>
```

新增只读 `AppIdentity`，启动时从当前程序集的 `AssemblyProductAttribute`、`AssemblyTitleAttribute`、`AssemblyInformationalVersionAttribute`/程序集版本读取身份，并校验 Product 与 Title 同为 `OneHistoryStudio`。以下消费者只能使用 `AppIdentity.Name/Version`，禁止再出现名称和版本字面量：

```text
AppPaths 数据目录
ShellConfig.AppName / AppVersion
异常对话框标题
启动与诊断日志
McpGateway serverInfo.name / version
关于页、状态页和发布信息
```

MCP网关不得维护自己的版本常量。网关通过构造参数接收同一身份对象，或读取同一个只读身份服务；测试替身也必须显式提供身份，防止重新引入默认字符串。

### 4.4 强制检查

1. 构建后读取 EXE 的 FileVersion、ProductVersion 和程序集属性；
2. 启动后读取窗口/Shell版本；
3. 调用 MCP `initialize` 检查 `serverInfo`；
4. 检查数据目录仍为 `%AppData%\OneHistoryStudio`；
5. 扫描 `src`（排除 `bin/obj` 和注释性历史文档），禁止出现独立版本字符串和消费者侧产品名字符串；
6. 以后升级版本只允许修改构建身份源，验收应证明其他出口自动变化。

## 5. 指令设计

### 5.1 AI 可读与可提议指令

| 指令 | 行为 | MCP 策略 |
|---|---|---|
| `prompt.get name=` | 查看默认描述、生效描述和当前修订 | readonly 可用 |
| `prompt.history name= [limit=]` | 查看修订历史 | readonly 可用 |
| `prompt.diff id=` | 查看某提案的旧值、新值和差异 | readonly 可用 |
| `prompt.propose name= text= reason= [evidence=]` | 提交待审核修改 | standard 可用 |
| `correction.list [name=]` | 查询勘误 | readonly 可用 |
| `correction.propose name= claim= correction= [evidence=]` | 提交勘误 | standard 可用 |
| `incident.list [name=]` | 查询工具事故记录 | readonly 可用 |
| `incident.record name= symptom= expected= actual= [evidence=]` | 记录失败现场 | standard 可用 |

MCP 工具名继续由导出层转换为 `prompt_get`、`prompt_propose` 等合法名称。

### 5.2 仅本地审核指令

| 指令 | 行为 |
|---|---|
| `mcp.pending` | 列出待审核提案 |
| `mcp.approve id= reviewer=` | 批准提案但暂不应用 |
| `mcp.reject id= reviewer= reason=` | 拒绝提案 |
| `mcp.apply id= reviewer=` | 生成新修订并设为生效 |
| `mcp.revert revision= reviewer= reason=` | 以旧修订生成一次新回滚修订 |

上述指令位于现有 `mcp.*` 硬排除域，因此不导出为 MCP 工具。管理页面的批准、拒绝、应用和回滚按钮必须经指令总线执行，不直接写数据库。

原 `mcp.desc` 保留一版兼容期：查看行为继续可用；保存和 reset 改为本地管理员快捷操作，并同样生成修订记录，不再直接覆盖唯一值。

## 6. 数据模型

建议新增以下表，旧 `mcp_descriptions` 在首次迁移时转成基线修订：

### 6.1 `mcp_prompt_revisions`

```text
id, command, description, parent_revision, source,
reason, created, created_by, applied, reverted_from
```

### 6.2 `mcp_prompt_proposals`

```text
id, command, base_revision, old_text, proposed_text,
reason, evidence, source_client, created,
status(pending/approved/rejected/applied), reviewer,
reviewed, review_note, applied_revision
```

### 6.3 `mcp_corrections`

```text
id, command, claim, correction, evidence,
source_client, created, status, linked_proposal
```

### 6.4 `mcp_incidents`

```text
id, command, symptom, expected, actual, evidence,
source_client, created, resolution, linked_correction
```

生效描述是“当前已应用修订”的投影，不再是唯一历史副本。所有时间统一保存 ISO 8601；所有来源至少区分 `UI / Console / MCP:<client>`。

## 7. 管理页面升级

V2.1.2 暂沿用 V2.1.1 页面框架，详情区增加：

- 当前修订号、更新时间和来源；
- 默认描述与生效描述；
- 待审核提案数量；
- 原文/新文 diff；
- 理由、证据、来源客户端；
- 批准、拒绝、应用、回滚按钮；
- 勘误和事故记录页签。

保存生效后，服务端下一次 `tools/list` 立即返回新描述；界面必须同时提示“已有 AI 会话可能缓存工具表，需要新任务或客户端刷新”。

## 8. 安全与一致性规则

1. `prompt.propose` 只能创建待审核记录，不能改变生效描述；
2. 提案必须绑定创建时的 `base_revision`，审核时若基线已变化则标记冲突，禁止静默覆盖；
3. 空描述、超过 2000 字符、未知指令继续拒绝；
4. 危险操作说明不得被删至无法表达副作用，界面给出警告但不靠文本替代服务端权限；
5. 删除提案采用状态变化，不物理删除审计记录；
6. 回滚也生成新修订，历史不可改写；
7. `readonly` 只开放读取，`standard` 才允许提案和事故记录；
8. 所有本地审核动作进入统一操作历史。
9. MCP JSON 请求体必须是有效 UTF-8；非法字节返回 JSON-RPC `-32700`，不得使用宽松解码写入替换字符；
10. 描述包含 Unicode 替换字符或疑似代码页替换形成的大量连续 `?` 时，创建、批准和应用阶段均拒绝，避免旧的损坏提案绕过入口校验。

## 12. 非目标

- 不允许 AI 无审核直接重写生效提示词；
- 不实现自动根据事故批量改写提示词；
- 不把权限边界仅写进提示词；
- 不在本版实现 MCP 协议级 `prompts/resources`；
- 不强制当前 Codex 任务热刷新工具目录。
