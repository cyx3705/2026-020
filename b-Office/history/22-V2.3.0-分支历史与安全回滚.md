> 文档性质：V2.3.0 工程实施与验收合同

## 0. 一句话定义

以裸仓库真实 Git 提交图为唯一历史真值，在左侧“分支历史”窗口显示
`父分支分叉点 -> 当前分支自有提交 -> HEAD`，并通过统一命令总线提供详情、差异预览、
生成恢复提交、本地硬重置和 `--force-with-lease` 五类操作。

`push_history` 仍是 OneHistoryStudio 操作留痕，不伪装成可以还原的 Git 推送批次。

## 1. 目标与边界

### 1.1 必须实现

1. 项目总览或继承树选中项目后，左侧独立停靠窗口自动显示该分支历史；
2. 普通分支以继承树父分支和 `merge-base` 确定分叉点，基础分支以首提交为基线；
3. 分叉点作为第一行基线，之后按时间正序显示当前分支第一父链提交；
4. 每行显示时间、短 SHA、提交说明、作者、分叉点/HEAD/合并标记和 origin 状态；
5. 右键节点可查看详情、预览与 HEAD 的差异、复制 SHA、生成恢复提交或本地硬重置；
6. 普通回滚追加恢复提交，不改写既有提交；硬重置只修改本地，绝不顺带强推；
7. 强制推送必须是独立命令并固定使用 `--force-with-lease`；
8. 所有 UI 操作继续组装命令并进入 `CommandBus`，不新增 UI 直调 Git 旁路。

### 1.2 明确不做

- 不把操作日志解释为历史推送批次；
- 不开发多分支合并图、rebase、cherry-pick、tag 或补丁导出；
- 不自动强制推送，不提供普通 `--force`；
- 不新增历史数据库表，不改写现有 `push_history` 表结构；
- 不因查看历史修改工作树、分支 HEAD 或项目文件。

## 2. 历史计算

### 2.1 父分支和分叉点

历史读取优先消费 `proj.tree cached=true` 的父子关系。缓存缺失或未包含所选分支时，
本轮只允许触发一次 `proj.tree refresh=true`，然后重新查找父节点。

- 普通分支：`git merge-base <parent> <branch>`；
- 基础分支：`git rev-list --max-parents=0 --reverse <branch>` 的首个提交；
- 分支不存在、父分支不存在或无法得到分叉点时，返回失败，不猜测任意 SHA；
- 历史提交使用第一父链，意外出现 merge commit 时保留并标记，不展开第二父链。

历史表固定把分叉点放在第一行，后续为 `fork..branch` 的自有提交。分页只裁剪自有提交，
分叉点始终保留；响应须返回总数、skip、limit 与 `HasMore`。

### 2.2 origin 状态

自动加载只读取 `refs/remotes/origin/<branch>` 的本地跟踪引用：

- 提交是远端引用祖先：`已推送`；
- 提交只存在本地：`仅本地`；
- 不存在远端跟踪引用或无法判断：`远端未知`。

只有 `proj.history remote=true` 或页面“刷新远端”入口允许先 fetch 所选分支。
fetch 失败只把远端状态降为未知，本地提交历史仍正常返回，并在摘要中说明失败原因。

## 3. 指令合同

| 指令 | 安全级别 | 作用 |
|---|---|---|
| `proj.history name= limit=200 skip=0 refresh=false remote=false` | readonly | 返回分支、父分支、分叉点、HEAD、远端状态与分页节点 |
| `proj.history.show name= sha=` | readonly | 返回提交元数据与文件变更摘要 |
| `proj.history.diff name= sha=` | readonly | 返回目标提交到当前 HEAD 的差异摘要与文本 |
| `proj.rollback name= sha= msg=` | dangerous | 恢复目标树并生成新提交，保留原历史 |
| `proj.reset name= sha=` | dangerous | 硬重置本地分支和工作树，不操作远端 |
| `proj.forcepush name=` | dangerous | 使用 `--force-with-lease` 更新 origin |

结构化结果至少包含：

- `BranchHistoryReport`：Branch、ParentBranch、ForkSha、HeadSha、RemoteHeadSha、
  RemoteState、TotalOwnCommits、Skip、Limit、HasMore、Entries；
- `BranchHistoryEntry`：Sha、ShortSha、Author、CommittedAt、Subject、ParentCount、
  IsForkPoint、IsHead、IsMerge、RemoteState；
- `CommitDetail`：提交元数据、父提交、文件变更列表和统计；
- `BranchDiffReport`：目标/当前 SHA、受影响提交数、文件数、统计和差异文本。

UI、CLI 和 MCP 统一消费上述命令。危险命令带 `ConfirmPrompt`，由现有宿主确认中继决定是否放行。

## 4. 安全约束

### 4.1 通用校验

1. 项目必须是 Git 登记工作树，并继续通过受管根直接子目录与重解析点检查；
2. SHA 必须经 `rev-parse <sha>^{commit}` 解析成完整提交号；
3. 目标必须是所选分支祖先，且位于分叉点至当前 HEAD 的允许范围；
4. 回滚和硬重置前 `git status --porcelain --untracked-files=all` 必须为空；
5. 确认文案必须包含分支、当前 SHA、目标 SHA、受影响提交数和文件数；
6. 迟到的异步读取结果不得覆盖已经切换到的新项目。

### 4.2 生成恢复提交

`proj.rollback` 先完成全部校验和预览，再把索引与工作树恢复为目标提交的树并创建新提交。
目标与 HEAD 内容相同时返回“无需恢复”，不制造空提交。基础分支和其他受保护分支允许此操作，
但仍必须二次确认。失败时不得继续 push。

### 4.3 本地硬重置

`proj.reset` 固定执行本地 `reset --hard <full-sha>`。受保护分支一律拒绝；成功消息必须明确
“远端未修改”，并在 origin 与本地分叉时提示使用独立 `proj.forcepush`。该指令不负责清理未跟踪文件。

### 4.4 强制推送

`proj.forcepush` 必须满足：非受保护分支、存在 origin 跟踪引用、分支和工作树仍有效。
固定使用 `git push --force-with-lease origin <branch>:<branch>`；lease 失效必须失败，不得降级为 `--force`。

三类写操作继续写入 `push_history`，action 分别为 `rollback/reset/forcepush`，message 记录目标、
操作前后完整 SHA 和结果摘要。留痕失败只告警，不掩盖主操作真实结果。

## 5. 页面交互

新增工具窗口 `history`，标题“分支历史”，默认停靠左侧。顶部显示当前分支、父分支、
分叉点、HEAD 和远端摘要；工具栏提供刷新、刷新远端、加载更早。中部使用虚拟化列表显示历史节点。

历史行右键菜单：

1. 查看提交详情；
2. 预览与当前版本差异；
3. 复制提交 SHA；
4. 生成恢复提交；
5. 硬重置到此节点。

受保护分支的硬重置入口禁用。详情和差异使用只读预览对话框；写操作只从结构化预览进入总线确认，
不得因双击行直接执行。继承树接入同一 `ProjectSelectionState`：左键同步当前项目，右键可查看历史、
打开项目、复制分支名或切换到历史窗口选择回滚目标。
