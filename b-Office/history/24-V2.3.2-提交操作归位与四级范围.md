# OneHistoryStudio V2.3.2 提交操作归位与四级范围

> 文档性质：V2.3.2 工程实施与验收合同  
> 基线版本：V2.3.1 -> 目标版本：V2.3.2  
> 日期：2026-07-24  
> 状态：**已交付**

---

## 0. 一句话定义

把全部 Git 提交与推送入口从项目总览归位到“项目操作 → 所选项目提交与推送”，通过一个提交描述、
一个四段范围选择器和“提交/推送”两个按钮，统一驱动当前/全部与仅子模块/分支及子模块四种组合。

## 1. 问题与修正目标

V2.3.1 在项目操作和项目总览各放置了一套子模块选项，并为父提交与子模块提交分别提供描述框，
造成入口分散、语义重复。项目总览应只负责浏览、搜索和选择项目，不承担 Git 写操作。

V2.3.1 的项目操作 XAML 还存在布局缺陷：新增的两条 `RowDefinition` 被加到“项目”区域，
“所选项目提交与推送”区域实际只有三行定义，却把控件放到第 3、4 行，窄停靠宽度下可能挤在末行。

V2.3.2 必须同时完成：

1. 项目总览恢复纯浏览；
2. 所有提交/推送入口集中到项目操作；
3. 全部模式共享一个提交描述，不再提供页面级 `submsg`；
4. 修正提交区域行定义，保证四段选择器、描述框和按钮不重叠；
5. 增加真正的“仅子模块”清理模式，并明确父 gitlink 可能暂时待提交。

## 2. 四段范围选择器

固定提供以下四项，默认选中“当前·分支及子模块”：

| 模式 | 项目范围 | 仓库范围 | 提交命令 | 推送命令 |
|---|---|---|---|---|
| 当前·仅子模块 | 当前选择 | 直属子仓库 | `proj.commit name=... msg=... target=submodules` | `proj.push name=... target=submodules` |
| 当前·分支及子模块 | 当前选择 | 子仓库 + 父分支 | `proj.commit name=... msg=... target=both` | `proj.push name=... target=both` |
| 全部·仅子模块 | 全部登记工作树 | 全部直属子仓库 | `proj.commitall msg=... target=submodules` | `proj.pushall target=submodules` |
| 全部·分支及子模块 | 全部登记工作树 | 子仓库 + 全部父分支 | `proj.commitall msg=... target=both` | `proj.pushall target=both` |

选择器为单个四段控件，四项等宽。文字允许两行并居中显示，不因停靠窗口变窄而覆盖相邻项。
当前模式要求存在当前项目；全部模式不依赖当前选择。`SelectedActionTitle` 随模式显示当前项目或全部工作树。

页面只保留一个 `SelectedCommitMessageBox`。它同时作为父分支和子模块提交描述；推送不消费描述，
但与提交共用相同范围。页面不再显示或发送 `submsg`。

## 3. 命令合同与兼容

四条既有命令增加可选参数：

```text
target=parent|submodules|both
```

| target | 语义 |
|---|---|
| `parent` | 只操作父分支，保持 V2.3.0 以前行为 |
| `submodules` | 只操作直属子仓库，不提交或推送父分支 |
| `both` | 子仓库先、父分支后，保持 V2.3.1 联动行为 |

兼容优先级固定如下：

1. 传入 `target` 时以 `target` 为准；
2. 未传 `target` 且 `submodules=true` 时等价 `target=both`；
3. 未传 `target` 且 `submodules=false` 或省略时等价 `target=parent`；
4. `submsg` 继续供旧 CLI/MCP 使用；为空时回退到 `msg`；正式页面不再发送；
5. `target` 使用 `AllowedValues` 约束，非法值由 `CommandBus` 在进入 Handler 前拒绝；
6. 不新增命令，运行时命令总数保持 106。

## 4. 服务与结构化结果

新增 `RepositoryTarget` 枚举：`Parent / Submodules / Both`。`ProjectService` 的单项和批量提交、
推送入口统一接收该枚举；命令层负责把 `target/submodules` 兼容参数解析成唯一枚举。

`CommitReport` 增加：

- `Target`：本次实际目标；
- `ParentExecuted`：是否尝试父提交；
- `ParentPointerPending`：是否有子 HEAD 已变化但父 gitlink 尚未提交。

`PushReport` 和批量报告增加实际目标及待收口父项目数量。完整结果继续进入 `CommandResult.Data`，
控制台只输出摘要和首个失败原因。

### 4.1 仅子模块提交

1. 只发现、预检和提交直属脏子仓库；
2. 不准备父仓库 LFS、不执行父 `git add/commit`；
3. 子仓库无变化时返回 `Skipped`；
4. 任一子提交成功后返回 `ParentPointerPending=true`；
5. 消息明确提示“父分支尚未记录新 gitlink，请执行分支及子模块完成收口”；
6. 部分失败保留已成功子提交，不自动 reset。

### 4.2 仅子模块推送

1. 要求子工作树干净、命名分支有效且存在 origin；
2. 允许父 HEAD gitlink 与子 HEAD 不一致，因为父分支不会被推送；
3. 只执行子仓库 `git push origin <branch>`；
4. 父远端保持不变，结果明确 `ParentPushed=false`；
5. 如父指针不一致，返回待收口提示但不把成功推送判为失败。

### 4.3 分支及子模块

保持 V2.3.1 安全合同：提交时子先父后；推送时要求父 HEAD 已记录子 HEAD，子推送全部成功后才推父。

## 5. 页面归位

### 5.1 项目操作

“所选项目提交与推送”区域按以下稳定顺序布局：

1. 动态作用域标题；
2. 唯一提交描述框；
3. 四段等宽范围选择器；
4. “提交”与“推送”按钮。

删除 `SelectedIncludeSubmodulesCheckBox`、`SelectedUseParentMessageCheckBox`、
`SelectedSubmoduleMessageBox` 及相关启用逻辑。修正该 Grid 为四条有效行，同时把“项目”区域恢复为三行。

按钮启用规则：

- 提交始终要求描述非空；
- 当前两种模式还要求当前项目非空；
- 全部两种模式不要求当前项目；
- 操作执行期间选择器、输入框和两个按钮统一禁用；
- 所有点击继续只组装命令并进入 `CommandBus`。

### 5.2 项目总览

完整删除“全部项目提交与推送” GroupBox、提交描述、子模块选项、提交/推送按钮、运行状态字段和事件。
页面只保留搜索、刷新、打开根目录、项目列表、选择同步和双击打开。

## 7. 发布与边界

- 版本只从 `src/App/App.csproj` 统一升级到 `2.3.2`；
- 不新增数据库迁移；
- 正式部署前备份为 `OneHistoryStudio-rollback-2.3.1-<时间>`；
- 自动化只使用临时仓库和本地裸远端；
- 真实项目只执行 Help、MCP、项目列表和页面只读检查；
