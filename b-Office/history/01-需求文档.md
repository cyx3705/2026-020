## 0. 一句话定义

OneHistory-V2.0 是基于 z-APPShell 框架派生的**个人项目管理工具**：以指令化方式提供
OneHistory 全项目库的 Git 分支/工作树管理能力（承接 b-Code-OneHistory-V1.0 的全部功能），
并融合 MyAPI-Lite 的 **DLL 模块热重载**机制作为能力扩展层——今后所有分散的小工具都以
模块 DLL 的形式装进这一个程序。

## 1. 背景与目标

### 1.1 背景

- 历史上积累了一批电脑控制与项目管理小工具，分散、页面杂乱、各自维护，效率低。
- b-Code-OneHistory-V1.0（WPF 单窗体）承载着 OneHistory 项目库的日常管理（裸仓库 +
  worktree 模式），功能已验证但架构无法扩展。
- z-APPShell 模板（基线 0.4.1-M4）已完成 M1~M4 并通过全部十条验收，具备五类标准窗口 +
  指令总线 + SQLite + 日志体系，正是为这类整合而生。
- MyAPI-Lite 提供了零依赖的 DLL 热重载托管模式（已冻结，2026-07-07），其
  ModuleHost / Invoker 机制可作为能力扩展的技术蓝本。

### 1.2 设计目标

| 编号 | 目标 |
|---|---|
| G1 | **功能对齐**：V1.0 的全部 Git 管理功能在 V2.0 中有等价实现，V1.0 可退役 |
| G2 | **一切皆指令**：全部功能先有指令、后有 UI，继承模板三条架构不变量 |
| G3 | **能力可扩展**：新小工具以模块 DLL 放入 Modules 目录即成为新指令域，主程序永不为单个工具改代码 |
| G4 | **操作可追溯**：每次提交/推送/删除留痕入库，表窗口可查历史 |
| G5 | **半月内交付**：依托模板派生流程（模板需求文档 §9），骨架半天、全功能两周内 |

### 1.3 非目标（首版明确不做）

- 不做 HTTP / MCP 对外服务（aimcp 接入现存问题，列为 P2 预留，见 §9-Q2）。
- 不做远程仓库托管配置（GitHub remote 沿用现有仓库既有配置）。
- 不修改 z-APPShell 的 AppShell.Core / Services / Shell 三个只读项目（除非按演进手册上报流程）。
- 不修改 MyAPI-Lite 本体（其已代码冻结；只移植其机制，不引用其进程）。
- 不做多用户 / 权限 / 网络协同。

## 2. 术语与既有资产

| 术语 | 含义 |
|---|---|
| 裸仓库 | `C:\OneHistory\OneHistory-Projects\OneHistory-Projects.git`，全部项目分支的唯一存储 |
| 工作树根目录 | `C:\OneHistory\OneHistory-Projects`，每个项目 = 一个分支 = 一个同名 worktree 文件夹 |
| 模板分支 | `0000-000-Template`，所有新项目分支的默认基础分支（受保护） |
| 受保护分支 | `0000-000-Template` / `main` / `master`，删除操作一律拒绝 |
| 模块（Module） | 放入 Modules 目录的 DLL，含 `ModuleInfoBase` 子类者暴露为指令域 |
| V1.0 | b-Code-OneHistory-V1.0\OneHistoryGitTool（被替代的旧工具） |
| 模板 / Shell | z-APPShell，基线 0.4.1-M4，见其 docs/TEMPLATE_VERSION.md |

## 3. 总体架构

```
┌────────────────────────────────────────────────────────┐
│ 模块层（Modules\*.dll，热重载）                            │
│   各历史小工具逐步迁移为模块 → 自动注册为指令域              │
├────────────────────────────────────────────────────────┤
│ App（派生应用层，本项目全部开发工作所在）                    │
│   · Git 项目管理指令域 proj.*                             │
│   · 模块托管指令域 module.*（移植 MyAPI-Lite 机制）         │
│   · 主窗口内容（项目总览视图）                              │
│   · 控制面板 JSON ＋ 菜单项 ＋ 数据表结构                   │
├────────────────────────────────────────────────────────┤
│ z-APPShell 模板（只读区，基线 0.4.1-M4）                   │
│   AppShell.Shell / AppShell.Services / AppShell.Core     │
│   五类标准窗口 · 指令总线 · SQLite · 日志 · 布局持久化       │
└────────────────────────────────────────────────────────┘
```

依赖铁律沿用模板演进手册 §2：依赖方向永远向下；AvalonDock 类型只出现在 Shell 内部；
模块 DLL 只依赖模块契约（BaseVariable 模式），不反向依赖 App。

## 4. 功能需求 A —— Git 项目管理（指令域 `proj`）

> 来源：V1.0 全部功能的指令化重写。V1.0 中可复用的纯逻辑类
> （WorktreeFileScanner / WorktreeLfsHelper / BranchNode 解析）允许移植源码到 App 层。
> 优先级：P0 必须（首版）｜ P1 应该 ｜ P2 可选

| 编号 | 需求描述 | 对应 V1.0 功能 | 优先级 |
|---|---|---|---|
| PJ-01 | `proj.list [filter=]`：列出全部 worktree（编号、分支名、路径、状态），支持关键字过滤 | 刷新工作树列表 + 搜索 | P0 |
| PJ-02 | `proj.create name= [base=0000-000-Template]`：创建分支 + worktree。校验：名称非空、无非法文件名字符、分支不存在、目标目录不存在；预览等价 git 命令后执行 | 创建分支+工作树 | P0 |
| PJ-03 | `proj.delete name=`：先移除 worktree 再强制删分支。受保护分支直接拒绝；其余走总线 ConfirmPrompt 二次确认（UI 与手输同一闸口） | 删除分支+工作树（强警告） | P0 |
| PJ-04 | `proj.tree`：输出分支继承树（基于裸仓库真实提交图），含每分支描述与最后提交时间 | Git 操作继承树 | P0 |
| PJ-05 | `proj.commit name= msg=`：对单个 worktree 执行大小检查 → LFS 处理 → git add . → commit。≥50MB 警告继续并留痕；≥100MB 检查 LFS 指针，未启用则确认，拒绝则跳过该项目 | 提交到本地仓库 | P0 |
| PJ-06 | `proj.push name=`：git push origin 分支名，结果回显 | 推送到 GitHub | P0 |
| PJ-07 | `proj.commitall msg=`：遍历全部 worktree 逐个执行 PJ-05 流程，汇总成功/跳过/拒绝/失败四类结果 | 一键推送全部到裸仓库 | P0 |
| PJ-08 | `proj.pushall`：推送全部分支到 GitHub（git push --all origin） | 一键推送 GitHub | P0 |
| PJ-09 | `proj.open name=`：在系统资源管理器中打开该 worktree 文件夹 | 打开工作树文件夹 | P1 |
| PJ-10 | `proj.scan name=`：仅执行大文件扫描并输出报告（≥50MB / ≥100MB 分级），不提交 | 推送前检查（独立化） | P1 |
| PJ-11 | `proj.repair`：worktree 断链批量修复（prune → 按分支清单重建），流程按主项目 Note.txt 既有方案实现，执行前二次确认 | Note.txt 手工修复方案 | P1 |
| PJ-12 | 裸仓库路径 / 工作树根目录 / 基础分支 / 大小阈值均为配置项（app.set/app.get 可读写），默认值取 §2 现值 | 仓库配置区 | P0 |
| PJ-13 | 长任务（commitall / pushall / repair）异步执行并上报进度，不阻塞 UI | —（V1.0 为 async） | P0 |

## 5. 功能需求 B —— 模块托管（指令域 `module`）

> 来源：MyAPI-Lite 的 ModuleHost / Invoker 机制**进程内移植**（判定见 §9-D3）。
> MyAPI-Lite 本体保持冻结不动；HTTP / MCP 部分首版不移植。

| 编号 | 需求描述 | 优先级 |
|---|---|---|
| MD-01 | 模块目录默认 `<应用数据目录>/Modules`（可配置）。放入/覆盖/删除 DLL 自动热重载（约 1s，800ms 防抖），无需重启 | P0 |
| MD-02 | 模块契约沿用 MyAPI-Lite 的 `ModuleInfoBase` 鸭子类型识别（按基类全名匹配），**既有为 MyAPI-Lite 编写的模块 DLL 不改一行即可装入** | P0 |
| MD-03 | 模块业务类的公共方法自动注册为指令：`<模块名>.<方法名> [参数=值 ...]`，与内置指令同表、help 自动收录；XML 注释成为帮助文本 | P0 |
| MD-04 | 参数绑定支持基本类型 + 默认值可省略；返回对象序列化为 JSON 回显控制台 | P0 |
| MD-05 | `module.list`：列出已加载模块（名称/版本/描述/方法数）；`module.reload`：手动整体重载；`module.dir [path=]`：查看/切换模块目录 | P0 |
| MD-06 | 模块隔离：模块方法抛出的异常由指令总线兜底（N-05），模块加载失败只下线该模块并告警，不影响宿主与其他模块 | P0 |
| MD-07 | 热重载后指令注册表同步增删；与内置指令重名时**拒绝加载该方法**并告警（不静默覆盖，沿用模板 §5.3 规则） | P0 |
| MD-08 | 模块可声明配套控制面板 JSON（放入模块旁或 panels 目录），面板按钮触发模块指令 | P1 |
| MD-09 | DemoModule（Calculator）作为验收样例模块随项目提供 | P0 |
| MD-10 | 对外 HTTP / MCP 暴露：预留，不在首版（见 §9-Q2） | P2 |
