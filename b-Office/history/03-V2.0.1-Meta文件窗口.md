## 0. 一句话定义

在每个项目的**一级子目录**中，以 `z` / `Z` 开头的文件夹视为该项目的**元文件夹**（Meta 文件夹）。  
V2.0.1 新增可停靠工具窗口 **「Meta文件」**，以类似「项目总览」的表格形式汇总整个项目库中的全部元文件夹，支持刷新与关键字查找，便于发现新加入的 Z 级一级目录。

---

## 1. 背景与动机

- OneHistory 项目库中，各项目工作树根下常放置以 `z-` 前缀命名的汇总/资料类一级文件夹，用于存放该项目的元数据、库文件索引、资料汇总等，与业务代码目录区分开。
- 示例：
  - `C:\OneHistory\OneHistory-Projects\2026-016-AD学习\z-AD库文件汇总`
  - 上述 `z-AD库文件汇总` 即该项目的 **Z 级一级文件夹**（元文件夹）。
- 目前「项目总览」只列 worktree / 分支本身，**看不到**各项目内部是否已有、新增了哪些元文件夹。
- 需要一个轻量窗口：跨项目扫一眼、能刷新、能搜，而不必逐个打开资源管理器。

---

## 2. 术语

| 术语 | 含义 |
|---|---|
| 项目库 / 工作树根 | `C:\OneHistory\OneHistory-Projects`（与 `proj` 配置中的工作树根一致，可经配置改写） |
| 项目一级目录 | 某 worktree 根目录下的**直接子文件夹**（深度 = 1，不递归子树） |
| Z 级一级文件夹 / 元文件夹 | 项目一级目录中，文件夹名以 `z` 或 `Z` 开头者（大小写不敏感匹配前缀） |
| Meta文件窗口 | 本版新增的可停靠工具窗口，窗口标题为「Meta文件」 |
| 项目总览 | 既有窗口（Id=`overview`），本版 UI 交互的参照对象 |

### 2.1 识别规则（定稿）

1. **扫描范围**：当前配置的工作树根下，每一个有效 worktree 目录（与 `proj.list` 同源清单）。
2. **深度**：仅扫描各项目根下的**直接子文件夹**，不深入二级及以下。
3. **命名**：文件夹名以 `z` / `Z` 开头即视为元文件夹（例如 `z-AD库文件汇总`、`Z-Notes`、`z资料` 均计入）。
4. **类型**：只认文件夹，忽略同名前缀的普通文件。
5. **非目标**：不解析元文件夹内部结构；不做内容索引；不做自动创建/重命名（本版只做发现与打开）。

## 3. 功能需求

### 3.1 工具窗口「Meta文件」

| 编号 | 需求描述 | 优先级 |
|---|---|---|
| MF-01 | 新增独立可停靠工具窗口，Id=`meta`，标题 **「Meta文件」**；默认停靠位置建议与「项目总览」同组（顶部标签组，可作为 `overview` 的 Tab 同伴，或并列 Top），具体默认布局实现自定，保持简洁 | P0 |
| MF-02 | 窗口内容为**表格列表**（交互形态对齐「项目总览」）：顶部有搜索框 +「刷新」按钮；主体为可排序观感的列表；底部一行状态提示 | P0 |
| MF-03 | 表格列至少包含：所属项目（分支/项目名）、元文件夹名、完整路径；可选列：最后修改时间（取文件夹 LastWriteTime，便于发现新加入项） | P0 |
| MF-04 | **刷新**：点击刷新（或执行对应指令）重新扫描项目库，检出新加入 / 已删除的 Z 级一级文件夹，并更新列表 | P0 |
| MF-05 | **搜索 / 过滤**：顶部搜索框按关键字即时过滤（匹配项目名、元文件夹名、路径中任一字段即可），行为对齐项目总览的搜索体验 | P0 |
| MF-06 | **双击行**：在资源管理器中打开该元文件夹（等价于对该路径执行“打开文件夹”）；若所属项目行需扩展，可另提供打开所属项目根目录的能力，首版以打开元文件夹本身为准 | P0 |
| MF-07 | 窗口一切操作按钮均组装指令文本经总线执行（架构不变量 1），控制台可见等价回显；列表数据与指令结果同源 | P0 |
| MF-08 | 启动或首次显示时可自动拉一次列表（与项目总览启动即 `proj.list` 的习惯一致）；之后以手动刷新为主（首版不做文件系统实时监视，避免噪声） | P1 |

### 3.2 指令域扩展（建议挂在既有 `proj` 下）

> 原则：先有指令、后有 UI。纯控制台须能列出 / 过滤元文件夹，不依赖打开「Meta文件」窗口。

| 编号 | 需求描述 | 优先级 |
|---|---|---|
| MF-10 | `proj.metalist [filter=]`：扫描全部 worktree 的 Z 级一级文件夹并列出；`filter` 对项目名 / 元文件夹名 / 路径做关键字过滤 | P0 |
| MF-11 | 列表输出字段与窗口表格同源（项目名、元文件夹名、路径，可选最后修改时间）；结果可供 UI 消费（与 `proj.list` → 项目总览同一模式） | P0 |
| MF-12 | `proj.metaopen path=` 或 `proj.metaopen name= meta=`：在资源管理器中打开指定元文件夹；非法路径 / 不存在时明确报错，不崩溃 | P0 |
| MF-13 | help 自动收录上述指令；示例写进指令 Example 字段 | P0 |

### 3.3 非目标（本版明确不做）

- 不递归扫描二级及以下目录中的 `z-*` 文件夹。
- 不自动创建、重命名、删除元文件夹。
- 不对元文件夹内容做全文检索或标签系统。
- 不修改 z-APPShell 的 AppShell.Core / Services / Shell（仅改 App 层，与 V2.0 纪律一致）。
- 不引入新的指令语法；沿用 §5.1 既有语法。

## 4. UI 草图（对照项目总览）

```
┌─ Meta文件 ─────────────────────────────────────────────┐
│  搜索: [______________]              [刷新]            │
├──────┬──────────────────┬──────────────────────────────┤
│ 项目 │ 元文件夹         │ 路径                         │
├──────┼──────────────────┼──────────────────────────────┤
│ 2026-016-AD学习 │ z-AD库文件汇总 │ C:\...\2026-016-AD学习\z-AD库文件汇总 │
│ …    │ …                │ …                            │
├────────────────────────────────────────────────────────┤
│ 共 N 个元文件夹 · 双击一行在资源管理器中打开            │
└────────────────────────────────────────────────────────┘
```

交互对齐约定：

| 项目总览（既有） | Meta文件（本版） |
|---|---|
| Id=`overview`，标题「项目总览」 | Id=`meta`，标题「Meta文件」 |
| 数据源 `proj.list` | 数据源 `proj.metalist` |
| 搜索过滤 worktree | 搜索过滤元文件夹 |
| 刷新重扫 worktree | 刷新重扫各项目下 Z 级一级文件夹 |
| 双击 → `proj.open` | 双击 → `proj.metaopen`（打开元文件夹） |

## 5. 验收要点（V2.0.1）

> 详细步骤可在开发完成后补入 `02-项目验收单.md`；此处给出出口标准。

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| A201-1 | 指令列表 | 控制台执行 `proj.metalist`，能列出已知示例（至少含 `2026-016-AD学习` 下的 `z-AD库文件汇总`）；`filter=` 生效 |
| A201-2 | 窗口存在 | `win.show name=meta` 可显示「Meta文件」窗口；布局可持久化 |
| A201-3 | 同源 | 窗口列表与 `proj.metalist` 同源；点刷新后控制台有等价指令回显 |
| A201-4 | 新加入可发现 | 在任一项目根下新建 `z-测试元文件夹`，点刷新后列表出现该项；删除后再刷新该项消失 |
| A201-5 | 搜索 | 输入项目名或 `z-` 关键字，列表即时过滤 |
| A201-6 | 双击打开 | 双击行后资源管理器打开对应元文件夹路径 |
| A201-7 | 边界 | 无元文件夹的项目不产生空行噪声；仅一级 `z*` 计入，二级目录中的 `z-*` 不出现 |
| A201-8 | 回归 | 既有 `proj.list` / 项目总览 / 继承树行为不变 |

## 6. 实现边界（给开发者 / AI）

1. **只改 App 项目**：新增视图（建议 `Views/MetaView.xaml(.cs)`）、在 `App.xaml.cs` 注册 `ToolWindowDescriptor`（Id=`meta`）、在 `proj.*` 指令集中增加 `metalist` / `metaopen`。
2. **扫描实现**：遍历 `proj.list` 得到的各 worktree 路径 → `Directory.EnumerateDirectories` 取直接子目录 → 名称前缀 `z`/`Z` 过滤；注意中文路径与权限异常（单项目失败应告警并跳过，不拖垮整次扫描）。
3. **不做框架改动**：不碰 AppShell.* 三目录；不新增 Shell 内置窗口类型。
4. **版本呈现**：窗口标题栏 / 关于信息中的产品版本可标为 `V2.0.1`（与交付包版本一致即可）。
