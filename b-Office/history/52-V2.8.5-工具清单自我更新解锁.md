# V2.8.5 工具清单自我更新解锁

> 日期：2026-08-03  
> 状态：源码与回归完成，待部署  
> 关联：`51-V2.8.4-活动坞迁出遗留修复.md` 的 L-14 / L-15

## 问题

`ToolManifestLoader.Load` 用**实时命令注册表**的一级指令域比对清单名，命中即判为
`模块名与内置指令域冲突`。注册表包含已加载模块贡献的指令，因此"清单名与自身指令域同名"的模块在加载后会
占住同名域，把自己的更新挡在门外，形成自锁。

当前模块中只有 `SE2SW` 命中：清单名 `SE2SW`，指令域 `se2sw`。`ActiveDock→dock`、
`GitHubConnection→github`、`StudioTools→三个域` 都不同名，因此从未暴露。

直接后果是 `SE2SW 3.1.2`（为服务宿主承载界面模块而补的空守）无法入槽，运行中的 `3.1.1` 持续在服务日志
留下 `创建 UI 模块 SE2SW.SE2SWUiModule 失败: Object reference not set to an instance of an object.`。
该告警使 V2.8.4 的"服务日志无 UI 模块告警"一项验收未通过。

## 修改

`ToolManifestLoader.Load` 增加可选参数 `isInstalled`。同名工具已在模块槽内时，本次是自我更新而不是抢占，
动态指令域检查跳过；`ToolSyncService` 传入按模块槽目录是否存在的判定。

`help`、`history`、`cls` 三个永久内置域在任何情况下都不放行，抢占防护本身不削弱：未安装的新工具仍然要
通过完整的指令域冲突检查。

## 影响

- `tool.scan` 不再把已安装工具的自我更新误报为 `(无效)`；
- 新工具首次入库的校验路径完全不变；
- 命令条数、MCP 投影与命令手册无变化，仍为 82 条源码命令；
- `StudioVersion.props` 提升为 `2.8.5`，AppShell 四包继续固定 `3.0.3`。

- Contracts 3 项通过，11 套功能 Smoke 全绿，版本投影为 `OHS 2.8.5, AppShell 3.0.3`。
