# V2.8.0 局域网自动发现与无感配对

> 日期：2026-07-30
> 状态：实施完成，候选验证通过；待真实 UAC、防火墙与两台 LAN 设备人工验收

## 目标

V2.8.0 面向不熟悉服务器地址、证书指纹和一次性配对码的普通客户端用户，在不修改已冻结 AppShell 的前提下，
把现有安全连接协议包装为 OHS 自有的自动发现与无感配对流程。

本版本保留 HTTPS、SHA-256 证书 pin、一次性配对码、设备 token、DPAPI、设备权限和撤销机制。客户端用户
不再手工抄写地址、指纹或配对码；OHS 通过可信 Private LAN 内的 UDP 对话取得这些信息，再调用 AppShell
3.0.3 已有的 `ShellServiceClient` 和 `/api/pair` 完成连接。

## 决策

- OHS 提升到 2.8.0；四个 `OneHistory.AppShell.*` 包继续固定为 3.0.3；
- AppShell 023 保持冻结，不修改源码、公开 API、协议或发布包；
- HTTPS 服务继续默认使用 `8738/TCP`，OHS 自动发现固定使用 `8739/UDP`；
- 默认设备角色继续是服务器，程序不得根据广播结果自动改变角色；
- 新客户端仍默认获得 `read` 权限，服务器管理员负责提升权限或撤销设备；
- MCP 继续只监听本机回环，不参与广播、配对或 LAN 开放；
- `conn.pair`、`lan.paircode` 以及手工地址/指纹命令保留为高级诊断和兼容入口，普通 UI 不再暴露。

首次证书指纹来自未认证 UDP，属于可信 Private LAN 下的 TOFU（Trust On First Use）模型，不能抵抗同一
局域网内主动伪装服务器。该限制必须在现行使用说明中明确，不得把自动化描述为密码学身份发现。

## 发现与配对协议

### 广播发现

客户端选择“客户端”后，在所有活动 Private IPv4 网卡上向子网广播地址和 `255.255.255.255:8739` 发送
最多 3 次 UTF-8 JSON 请求，总等待时间为 2 秒。单个报文不得超过 4 KiB。

发现请求固定包含：

- 协议标识 `ohs-discovery/1`；
- 随机 `requestId`；
- 产品名 `OneHistoryStudio`；
- 客户端 OHS 版本。

服务器只在 LAN 已启用、绑定地址属于当前活动 Private 网卡且证书已配置时响应。响应使用 UDP 单播返回请求
来源地址，包含并回显 `requestId`，同时返回：

- `serverId`、服务器显示名和机器名；
- 实际 HTTPS 端口；
- OHS 产品版本和最低客户端版本；
- 当前服务器证书 SHA-256 指纹。

客户端以 UDP 响应的来源 IP 和响应端口构造 `https://ip:port/`，不得直接采用报文提供的主机地址。响应必须
通过协议、requestId、产品、版本、Private IPv4、端口和 64 位指纹校验，并按 `serverId` 去重。

### 自动配对票据

发现阶段不批量生成配对码。客户端选定服务器后，向该服务器 `8739/UDP` 单播发送票据请求，包含：

- 新随机 `requestId` 和 `nonce`；
- 客户端 `DeviceId`；
- 当前 Windows 机器名作为设备显示名；
- 目标 `serverId`。

服务器为该请求生成 30 秒有效的一次性配对码，并把票据绑定到配对码、DeviceId、UDP 来源 IP、nonce 和
到期时间。响应回显 requestId、nonce 和 serverId，并只单播给请求来源。

AppShell `/api/pair` 的公开请求形态保持不变，不增加 nonce 参数。OHS `LanDeviceStore.Pair` 消费配对码时必须
同时核对 DeviceId、HTTPS 来源 IP、有效期和未使用状态；nonce 用于 UDP 请求与响应关联，避免客户端接受旧
响应。成功或失败消费后均使配对码失效，错误设备、错误来源、超时和重放全部拒绝。

### 建立连接

客户端使用发现到的地址和指纹创建临时 `ShellServiceClient`，调用现有 `PairAsync`。成功后：

1. token 按现有规则写入当前用户 DPAPI；
2. bootstrap 保存客户端角色、ServerId、HTTPS 地址和证书指纹；
3. 客户端自动重启并使用正式 profile 连接；
4. 页面显示“只读，等待服务器授权”，直到服务器把设备提升为 `operate` 或 `admin`。

配对或 HTTPS 校验失败时不得保存半成品 profile 或 token，也不得自动降级为 HTTP、忽略证书错误或改用另一
服务器。

## 客户端体验

- 用户在“连接与端口”选择客户端后立即开始搜索；
- 发现一个服务器时自动申请票据、配对、保存并重启，不再要求额外点击；
- 发现多个服务器时显示服务器名、机器名和地址，用户只需点选一个；
- 未发现服务器时显示简短失败状态和“重试”；
- “高级”折叠区保留手工 HTTPS 地址、证书指纹、设备名称和配对码，默认不展开；
- 已保存客户端启动连接失败时自动发现并优先匹配原 ServerId；匹配成功后更新 DHCP 变化后的地址；
- 未匹配到原 ServerId 时不得自动切换到其他服务器，应保持断开并进入服务器选择状态；
- 读权限拒绝写操作时统一提示“当前客户端为只读，等待服务器授权”，不向普通用户显示 scope 或 HTTP 状态码。

服务器页面继续显示已配对设备、权限、最近连接和撤销状态。服务器管理员仍通过现有设备命令修改权限或撤销
设备；本版本不让客户端自行申请或提升权限。

## 服务端与机器配置

- 新增 OHS 自有的 UDP 发现服务，随 ServiceHost 生命周期启动和释放，不新增独立 EXE 或 Windows 服务；
- 发现服务只监听已配置的 Private IPv4 和 UDP 8739，不监听 Public 网卡或 `0.0.0.0`；
- `lan.configure` 的 UAC 机器配置同时建立 TCP 业务端口和 UDP 8739 的 Private profile 入站规则；
- 关闭 LAN 时对称移除本版本创建的 TCP、UDP、URLACL 和 HTTPS 绑定；
- 证书创建、轮换、清理、HTTPS URLACL 和 TCP 防火墙规则保持现有所有权与回滚保护；
- UDP 端口冲突、监听失败或防火墙配置失败必须进入 `lan.status` 和日志，不能阻止本机回环服务启动；
- 广播请求与票据申请按来源 IP 限流；无效报文不得生成配对码、设备记录或普通日志洪泛。

## 实施

1. 在 OHS Connection 组件增加发现报文模型、编解码、客户端和 ServiceHost 生命周期内的 UDP 响应器；
2. 扩展 `LanDeviceStore` 的临时配对码状态，使自动票据绑定 DeviceId、来源 IP 和 nonce，同时保持现有
   `IDevicePairingProvider` 合同；
3. 调整 LAN 机器配置 payload、UAC helper、状态和清理逻辑，加入 UDP 8739 Private 防火墙规则；
4. 重构连接设置页为搜索状态、单服务器自动流程、多服务器选择和折叠高级入口；
5. 在客户端启动连接失败时执行按 ServerId 的自动重发现，不改变默认服务器角色；
6. 更新 `conn.*`、`lan.*` Help 元数据、命令手册数据反序列化和现行使用说明；
7. 修改 `StudioVersion.props` 为 2.8.0，AppShell 包版本保持 3.0.3；
8. 完成定向开发验证后形成 `b-Publish/candidate`，正式发布、部署和回滚留到发布候选审核阶段。

## 边界与回滚

- 本版本不修改 AppShell 023，不改变 `/api/pair`、Bearer token、WebSocket、MCP 或模块协议；
- 不使用 HTTP，不允许跳过证书校验，不把 token、配对码或指纹写入普通日志；
- 不自动修改 Windows 网络类别，只接受已经属于 Private 的活动网卡；
- 不新增正式数据数据库迁移；临时发现和配对票据只在内存保存；
- 回滚到 2.7.12 时自动发现入口消失，但既有 bootstrap、证书、设备 token 和手工配对仍可继续使用；
- 本次施工未修改 AppShell 包、正式 `z-Package` 或部署树，只生成 `b-Publish/candidate`。
