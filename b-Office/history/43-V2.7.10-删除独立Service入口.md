# V2.7.10 删除独立 Service 入口

> 日期：2026-07-29
> 目标版本：OneHistoryStudio 2.7.10
> AppShell 基线：3.0.3
> 状态：已部署，待人工重启复验

## 1. 目标

删除仓库根目录下已退出产品构建、但仍被测试和现行文档保留的 `b-Code-Studio.Service` 遗留入口。
OneHistoryStudio 继续使用单一产品程序：

```text
OneHistoryStudio.exe                    WPF 前端
OneHistoryStudio.exe --service-host     常驻后台服务
```

本次只清理重复入口和相应治理残留，不改变服务组合、命令合同、端口、数据目录、MCP/Web 协议、模块行为或
AppShell 版本。

## 2. 当前事实

`b-Code-Studio.Service` 已不在 `OHS.sln`，其项目声明为 `OutputType=Library`，程序集名为
`OneHistoryStudio.LegacyServiceHost`，不会进入正式发布树。目录只剩：

```text
b-Code-Studio.Service/
├─ Program.cs
├─ Studio.Service.csproj
└─ app.manifest
```

正式服务入口已经位于 `b-Code-Studio/Program.cs`：`--service-host` 调用 AppShell `ServiceHost.Run`，
`--no-autostart` 控制首次运行注册，`--generate-manual` 使用同一 `StudioServiceCompositionFactory` 生成命令手册。
前端在服务不可达且当前节点为服务器时，也通过同一个 `OneHistoryStudio.exe --service-host` 启动后台进程。

遗留项目继续存在只产生四类负担：

1. `VersionProjectionSuite` 仍评估一个非产品项目，并把 AppShell 包消费点计为五处；
2. `LanSingleExeSuite` 一边断言产品是单 EXE，一边要求遗留项目必须存在；
3. 发布脚本仍把不存在于产品解决方案的目录纳入源码洁净门禁；
4. 根 README 和现行手册仍把该目录描述为常驻后台服务入口，与运行事实冲突。

## 3. 边界

### 3.1 删除

- 删除整个 `b-Code-Studio.Service` 目录及其中三个文件；
- 删除测试、发布脚本、根 README、产品 README 和现行 `meta` 手册对该项目的现行依赖；
- 删除“五处 AppShell PackageReference”的当前叙述，统一为 Studio 的四处固定包引用；
- 删除测试中使用 `OneHistoryStudio.Service.exe` 模拟当前服务入口的写法。

### 3.2 保留

- 保留 `b-Code-Studio/Service/`。该目录包含当前有效的 `StudioServiceCompositionFactory`、服务内置命令和
  远端命令数据反序列化，不是本次删除对象；
- 保留 `OneHistory.AppShell.ServiceHost 3.0.3` 包引用；主 EXE 同时承担前端和服务宿主入口，仍需要该包；
- 保留 `OneHistoryStudio.exe --service-host [--no-autostart]`、`--generate-manual`、LAN 安装/移除辅助入口；
- 保留前端按需启动后台服务和关闭前端后服务继续运行的行为；
- 保留已交付 `versions/` 和 `evidence/` 中关于旧 Service 工程或旧 EXE 的历史事实，不回写历史；
- 部署脚本继续检测 `OneHistoryStudio.Service` 旧进程名至少一个版本周期，作为从旧部署升级时的阻断保护。
  该兼容检查不表示旧入口仍受支持，也不得使旧文件重新进入正式包。
