## 1. 版本目标

V2.1.4 不继续扩张业务能力，集中完成三件事：

1. 整理程序文档，建立清晰入口和“当前文档/历史记录”边界；
2. 把注册表中的 `help` 升级为可搜索、可视化、可供 MCP 使用的统一指令手册；
3. 完成版本号、构建、回归、Publish 和部署区同步，正式交付 V2.1.4。

V2.1.4 同时吸收最后一项界面归位：Git 文件格式规则从“项目总览”迁入正式“项目操作”窗口。窗口继续使用布局 ID `projops`；项目总览恢复为纯列表，规则后端和 `git.rule.*` 不变。

## 2. 当前 Help 基线

现有 `help` 已由 `BuiltinCommands` 注册，支持：

```text
help
help win.dock
help DemoModule.Add
```

它从 `CommandRegistry` 动态读取，模块热重载后自动增删；`CommandSchemaExporter` 没有排除 `help`，readonly 白名单也包含 `help`，因此 **help 已经是 MCP 工具**。V2.1.4 不重复制造第二个“AI help”，而是把现有能力在命令集页、图形帮助页和文档中明确呈现并验收。

## 3. 文档治理

### 3.1 新增入口

新增 `docs/README.md` 作为唯一文档入口，按以下类别组织：

| 类别 | 内容 |
|---|---|
| 当前版本 | 当前需求、命令手册、配置、MCP 接入、发布说明 |
| 架构与开发 | 架构不变量、二次开发、模块开发、数据与安全边界 |

旧文档首版不批量改名，避免打断已有链接。对重复或过时内容增加状态头和指向当前文档的链接；确认无外部引用后再规划目录迁移。

### 3.2 必须形成的现行手册

| 文档 | 内容 |
|---|---|
| `命令手册.md` | 自动生成的全部指令域、参数、示例、危险位和 MCP 状态 |

命令手册不得人工复制维护。生成器读取 `CommandRegistry.All()` 和 MCP 导出结果，输出确定性 Markdown；同一版本重复生成应得到相同内容。

## 4. Help 功能升级

### 4.1 控制台行为

保留兼容语法：

```text
help
help proj.commit
```

增强项：

- 全量列表按指令域分组并显示每域数量；
- 详情显示 Summary、参数类型、必填、默认值、允许值、示例；
- 显示危险确认、UI线程和 MCP 暴露状态；
- 未知指令继续给出相近候选；
- 模块指令与内置指令使用相同格式；
- 长列表输出保持可读，不破坏现有控制台滚动。

若扩展现有 `help` 参数会触碰框架基线，必须按模板演进流程回灌，不能只在 OneHistoryStudio 私自分叉。也可以先由 App 层 `command.list/show` 提供筛选，`help` 保持兼容。

### 4.2 Help 图形页

新增 `Help` 工具窗口或在命令集页提供完整 Help 页签，至少包含：

- 指令域树和搜索；
- 指令摘要、参数表和示例；
- “执行 help”按钮；
- “查看 MCP 形态”按钮；
- “复制示例”按钮；
- MCP 可见、策略、危险拒绝和硬排除标记；
- 模块热重载后自动刷新。

按钮必须组装并执行既有指令：

```text
help <command>
mcp.schema name=<command>
```

硬排除指令点击“MCP 形态”时显示排除原因，不伪造 Schema。

### 4.3 MCP Help 验收

Codex 侧至少验证：

1. `help` 无参数能列出当前指令；
2. `help command=proj.list` 返回参数和示例；
3. 模块加载后 `help command=DemoModule.Add` 可查，模块下线后不再列为有效指令；
4. help 只能提供说明，不能绕过 readonly/standard 和 ConfirmPrompt；
5. 命令集页明确标出 help 对应的 MCP 工具名和策略状态。

## 5. 文档与代码单一真值

```text
CommandDescriptor
  ├─ help 控制台输出
  ├─ 命令集管理页
  ├─ MCP tools/list Schema
  └─ 命令手册 Markdown 生成器
```

四个出口必须来自同一个注册元数据，不允许各自维护 Summary、参数或示例。提示词自定义只影响 MCP 生效描述，不应篡改命令自带 Summary；勘误应通过 V2.1.2 治理链形成可审计修订。
