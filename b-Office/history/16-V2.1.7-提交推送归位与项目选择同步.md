# OneHistoryStudio V2.1.7 · 提交推送归位与项目选择同步

> 日期：2026-07-18
> 状态：已部署交付；WPF 自动截图受系统接口限制
> 前置版本：V2.1.6（Fable5 代码质量整备版）
> 性质：既有界面能力归位与选择同步，不新增 Git 或 MCP 指令

## 1. 版本目标

V2.1.7 只完成三件事：

1. 撤下独立的“提交推送”动态面板，不再要求用户重复填写分支名；
2. 把单项目提交、推送归入“项目操作”，把全部项目提交、全部分支推送归入“项目总览”；
3. 在项目总览选择项目后，自动同步“项目操作”的“基础分支 / 当前项目”。

本版不修改 `proj.commit`、`proj.push`、`proj.commitall`、`proj.pushall` 的参数、确认规则或后端实现，不新增平行指令，不改变 Git 历史、LFS 检查、操作留痕和 MCP 暴露策略。

## 2. 当前问题

V2.1.6 仍由 `SeedProjectPanels` 写入 `panels/projpush.json`，形成独立“提交推送”窗口：

```text
分支名称: [____________]
提交描述: [一键推送更新]

[提交到本地仓库] [推送到 GitHub]
[一键提交全部工作树] [一键推送全部分支]
```

它存在三个问题：

- 项目总览已经知道所有项目，项目操作也已有当前项目选择，独立面板仍要求再输一次分支名；
- 单项目动作与批量动作混在一个窗口，职责不清；
- 用户从总览选中项目后，项目操作不会自动跟随，必须再次选择。

V2.1.7 不重做提交逻辑，只把现有四个入口归到已有页面。

## 3. 页面职责冻结

### 3.1 项目操作：所选项目动作

在现有“项目”区与“Git 文件规则”区之间增加“所选项目提交与推送”区：

```text
新项目名称:              [________________]
基础分支 / 当前项目:     [2026-018-MyAPI ▼]
[创建工作树] [打开所选项目] [刷新项目]

所选项目提交与推送 · 2026-018-MyAPI
提交描述: [一键推送更新________________]
[提交到本地仓库] [推送到 GitHub]

Git 文件规则 · 2026-018-MyAPI
...
```

固定映射：

```text
提交到本地仓库
proj.commit name=<基础分支/当前项目> msg=<提交描述>

推送到 GitHub
proj.push name=<基础分支/当前项目>
```

约束：

- `name=` 只能来自“基础分支 / 当前项目”，不得来自“新项目名称”；
- 提交描述是页面内普通文本框，不写入 settings、SQLite 或项目文件；
- 未选择当前项目时，提交和推送按钮均不可用；
- 提交描述为空时，提交按钮不可用；推送按钮不依赖提交描述；
- 执行期间禁用对应按钮，完成后恢复，防止重复点击产生并发 Git 操作；
- `proj.commit` 的大文件检查、LFS 询问和结果分类保持现状；
- 成功或失败都继续经 `CommandBus` 产生来源为 `UI` 的正常控制台日志；
- 单项目提交成功后可刷新项目状态，但不得改写当前选择和新项目名称。

### 3.2 项目总览：批量动作

在项目列表下方增加“全部项目提交与推送”区：

```text
项目列表
┌──────────────────────────────────────────────┐
│ #  分支 / 项目       最后提交       路径      │
└──────────────────────────────────────────────┘

全部项目提交与推送
统一提交描述: [一键推送更新________________]
[提交全部工作树到本地仓库] [推送全部分支到 GitHub]
```

固定映射：

```text
提交全部工作树到本地仓库
proj.commitall msg=<统一提交描述>

推送全部分支到 GitHub
proj.pushall
```

这里必须保留两个不同概念：

- `proj.commitall` 遍历全部已登记工作树并分别提交；
- `proj.pushall` 执行裸仓库的 `git push --all origin`，推送全部本地分支。

约束：

- 批量提交描述为空时，仅禁用“提交全部工作树”；
- `commitall` 和 `pushall` 继续使用现有 `ConfirmPrompt`，页面不再制造第二套确认框；
- 用户拒绝批量指令最外层 `ConfirmPrompt` 时，处理器不得启动；逐项目 LFS 询问的拒绝/跳过仍按既有四类结果汇总，不引入事务式回滚；
- 进度和四类汇总继续由既有指令回显到控制台；
- 批量提交完成后刷新总览的最后提交时间；
- 搜索过滤只影响列表显示，不改变批量操作的“全部工作树/全部分支”语义。

### 3.3 原提交推送窗口退役

V2.1.7 不保留空白窗口或兼容壳：

- 删除 `SeedProjectPanels` 对 `projpush.json` 的生成；
- `projpush.json` 是程序内置面板，加入 `StartupMigrations` 的 V2.1.7 一次性回收步骤；
- 迁移后 `win.list`、视图菜单和布局中不再出现 `projpush`；
- 旧布局含 `projpush` 节点时，由现有“未注册窗口丢弃”机制清理，不阻断启动；
- 四个动作全部归位后再回收面板，禁止先删入口后补功能；
- 不保留第二份提交描述，不让项目操作、项目总览与隐藏 JSON 面板同时维护同一能力。

当前 `SeedProjectPanels` 只负责这一份面板。移除 `projpush` 后，应连同空方法、调用点和 `SeedPanelIfMissing` 一并删除，避免留下无职责代码。

## 4. 项目选择同步

### 4.1 共享状态

沿用 V2.1.5 `CommandSelectionState` 的轻量模式，新增应用级纯内存 `ProjectSelectionState`：

```text
项目总览选择一行
        ↓ 只写 CurrentProjectName
ProjectSelectionState
        ↓ Changed 事件
项目操作
        ↓ 更新“基础分支 / 当前项目”并加载 Git 规则
```

`ProjectSelectionState` 只保存一个项目名字符串和变更事件，不保存 `WorktreeInfo`、项目列表、Git 状态、提交描述或规则数据。

### 4.2 同步规则

- 项目总览单击某行即更新当前项目；双击仍执行 `proj.open`，不改变原语义；
- 项目操作手动选择已登记项目时也更新共享状态，使两边保持同一个“当前项目”；
- 项目操作收到外部选择后，选中对应 ComboBox 项并通过 `git.rule.list` 刷新规则；
- 项目操作尚未创建时，后创建的窗口读取 `CurrentProjectName` 并补载当前项目；
- 总览搜索导致当前行暂时不可见时，不清空共享选择；
- `proj.list` 全量刷新确认项目已不存在时，清空失效选择，不保留陈旧项目；
- 创建项目成功后，把新项目写入共享状态；项目总览下次刷新后选中该项目；
- “新项目名称”始终是独立输入，不参与当前项目同步；
- 当前选择不写入 SQLite、settings、布局文件或 Git 仓库，重启后按正常项目列表初始化。

### 4.3 防循环和异步竞态

两个页面在程序性更新控件时使用抑制标志，避免：

```text
总览写状态 → 项目操作改 ComboBox → 再写相同状态 → 重复加载
```

状态层对大小写不敏感的相同项目名不重复触发 `Changed`。异步 `proj.list` / `git.rule.list` 返回后必须再次核对当前项目名，旧请求不得覆盖用户后来选中的项目。

## 5. 指令和安全边界

V2.1.7 继续只消费现有指令：

| 页面 | 按钮 | 指令 | MCP / 安全语义 |
|---|---|---|---|
| 项目操作 | 提交所选项目 | `proj.commit name=... msg=...` | standard；既有 LFS 确认链 |
| 项目操作 | 推送所选项目 | `proj.push name=...` | standard |
| 项目总览 | 提交全部工作树 | `proj.commitall msg=...` | dangerous；本地二次确认 |
| 项目总览 | 推送全部分支 | `proj.pushall` | dangerous；本地二次确认 |

禁止事项：

- 不新增 `project.commit.selected`、`overview.commitall` 等 UI 专用指令；
- 不直接调用 `ProjectService.CommitAsync/PushAsync`；
- 不绕过 `CommandBus`、`ConfirmPrompt`、LFS 检查或 `HistoryRecorder`；
- 不把批量危险指令改为 MCP standard 可见；
- 不在 UI 里自行执行 `git add`、`git commit` 或 `git push`；
- 不修改 V2.1.6 的代码质量整备边界和框架回灌成果。
