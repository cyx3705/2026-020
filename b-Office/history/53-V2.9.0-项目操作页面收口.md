# V2.9.0 项目操作页面收口

> 日期：2026-08-04
> 状态：实施与开发候选验证完成

## 目标

V2.9.0 收紧“项目操作”页面的信息层级和操作密度，把分散在多行、多个按钮区的同类动作合并成三块稳定工作面：

1. 项目选择与新建；
2. 提交与推送；
3. Git 文件规则。

本版只调整项目操作页及其直接命令合同，不修改 AppShell、模块注册器、Git 数据目录、项目历史、发布结构或
前后端协议。OHS 提升到 `2.9.0`，四个 AppShell 包继续固定为 `3.0.3`。

## 当前事实

### 项目栏

当前“项目”区使用三行布局：新项目名称、`基础分支 / 当前项目`、独立按钮行。按钮包括“创建工作树”、
“打开所选项目”和“刷新项目”。创建工作树时，当前项目仍作为 `proj.create base=<当前项目>` 的基底。

“打开所选项目”与项目总览的打开能力重复；删除该页面按钮不等于删除 `proj.open`，也不影响项目总览继续打开
工作树。

### 提交与推送栏

当前组标题为“所选项目提交与推送”，提交描述输入框、四段范围选择和提交/推送按钮分占多行。提交与推送按钮
位于最下方，导致用户在输入描述后还要再次移动视线和鼠标。

### Git 文件规则栏

当前规则动作分散在三处：

- Pattern 输入框右侧的“添加格式/目录”；
- 覆盖信息区中的“扫描覆盖”“查看未决”“规则建议”“同步模板基线（预览）”；
- 表格下方的“保存修改”“删除规则”“重新读取”。

“扫描覆盖”和“重新读取”最终都进入 `LoadRulesAsync`，差别只是前者以 `refresh=true` 忽略台账缓存，后者使用
缓存；两个入口没有继续并存的价值。

`git.rule.gaps` 与 `git.rule.suggest` 都先取得同一份格式台账，再分别输出未决清单和处置建议。页面把它们拆成
两个按钮会造成一次治理动作被人为分成两次。

`git.rule.sync` 的作用是把模板项目的规则 baseline 块同步到目标项目。它不会覆盖项目自身 managed 块或块外
手写内容，也不会删除文件、提交、推送或重写历史。页面当前只执行 `apply=false` 预览，实际写入仍需在控制台
显式执行 `apply=true`；V2.9.0 保留该安全边界。

## 页面布局

### 项目

“项目”组改为两行、三列布局：标签、可伸缩输入框、紧邻动作按钮。

| 行 | 标签 | 输入 | 右侧按钮 |
|---|---|---|---|
| 1 | 新项目名称 | `NewProjectNameBox` | `新建` |
| 2 | 当前项目 | `CurrentProjectBox` | `刷新` |

- 删除 `OpenProjectButton` 和 `OnOpenClick`；
- 删除界面中的“基础分支”字样，但不改变创建语义：新项目仍以当前项目作为 `base`；
- “新建”继续执行 `proj.create`，成功后清空名称、刷新列表并选中新项目；
- “刷新”继续执行项目列表刷新，并保留未保存规则的保存、放弃、取消保护；
- `proj.open` 命令及项目总览的打开入口保持不变。

### 提交与推送

第二个组标题统一为“提交与推送”。保留当前/全部与仅子模块/分支及子模块四段范围选择，不改变
`ProjectOperationMode` 或 `proj.commit/push/commitall/pushall` 的命令生成规则。

提交描述行改为四段：`提交描述` 标签、可伸缩文本框、`提交`、`推送`。两个动作按钮紧邻输入框右侧；忙碌状态、
当前项目要求和空描述禁用逻辑保持不变。`SelectedActionTitle` 继续显示“当前项目 · 名称”或“全部工作树”，用于
明确四段范围选择的实际目标。

布局不得使用固定页面宽度。文本框占剩余空间，按钮使用稳定 Auto 宽度；在项目操作窗格的最窄回归宽度下，
控件不得重叠或挤出宿主。

### Git 文件规则

Pattern 输入框独占一行。其下建立一个单排规则动作条，按钮顺序固定为：

```text
添加规则 | 刷新规则 | 未决与建议 | 同步基线 | 保存修改（n） | 删除规则
```

- “添加规则”读取上方 Pattern 输入；
- “刷新规则”合并原“扫描覆盖”和“重新读取”，统一执行未保存修改保护，然后强制刷新台账与声明规则；
- “未决与建议”执行新的 `git.rule.review`；
- “同步基线”仍只执行 `git.rule.sync ... apply=false`，通过 Tooltip 说明它只预览模板 baseline 同步；
- “保存修改（n）”与“删除规则”的状态机不变；
- 删除原覆盖信息 Border 中的独立按钮组和表格下方按钮组，覆盖率摘要仍保留在表格上方；
- 动作条在常规右侧窗格保持一排；窄宽时允许横向滚动，不把按钮折成多排，也不得裁切按钮文字。

## 命令与代码

### 规则刷新

页面删除 `OnScanCoverageClick`、`OnReloadRulesClick` 及对应两个按钮字段，合并为一个
`OnRefreshRulesClick`。统一流程为：

1. 调用 `EnsureDirtyRulesHandledAsync("刷新规则")`；
2. 调用 `LoadRulesAsync(project, refresh: true)`；
3. 在一次忙碌状态内并行读取 `git.rule.scan refresh=true` 与 `git.rule.list`；
4. 使用现有 `MergeRows` 原子替换表格和覆盖率摘要。

项目选择后的自动加载继续使用 `refresh=false`，避免每次切换都强制全量扫描。`git.rule.scan` 和
`git.rule.list` 继续作为独立的控制台、MCP 与诊断合同，不新增重复的 `git.rule.refresh` 命令。

### 未决与建议

删除公开命令 `git.rule.gaps` 和 `git.rule.suggest`，新增一个只读命令：

```text
git.rule.review name=<项目名>
```

`name` 省略时仍允许审查全库。命令只扫描一次格式台账，同时返回：

- 按影响文件数排序的未决格式与目录候选；
- 可自动判断的忽略、Git、Git+LF、Git+LFS 建议；
- 无法安全判断、必须人工决定的未知格式；
- 覆盖率、未决文件数和建议可覆盖文件数摘要。

新增 `GitRuleReviewReport` 作为结构化 Data，包含裁剪后的未决 `InventoryReport`、全量建议和未知格式集合。
`StudioCommandDataDeserializer` 增加 `git.rule.review` 映射。`FormatInventoryService` 增加一次扫描后同时构造缺口与
建议的 `ReviewAsync`，公共 `GapsAsync/SuggestAsync` 和重复渲染代码随旧命令删除；纯计算部分保持可单独测试。

V2.9.0 是主版本升级，允许移除上述两个旧命令。其余规则命令名称、参数、只读性和确认策略不变；源码命令总数
预计由 82 条变为 81 条，最终数字必须由运行时命令手册生成，不手工改写。

## 实施范围

- `ProjectOperationsView.xaml`：重排三个区域并建立单排规则动作条；
- `ProjectOperationsView.xaml.cs`：删除页面打开入口，调整新建、刷新、提交与推送控件状态；
- `ProjectOperationsView.Rules.cs`：合并刷新处理器和未决建议处理器，收口忙碌状态与按钮引用；
- `GitRuleCommands.cs`：以 `git.rule.review` 替换 `git.rule.gaps/suggest`；
- `FormatInventoryService.cs` 与模型文件：增加组合审查结果并消除重复扫描、筛选和渲染；
- `StudioCommandDataDeserializer.cs`：增加组合结果反序列化；
- 当前使用说明、项目库与备份、发布与升级及运行时命令手册同步当前事实；
- 历史版本文档保持原样。

不借机修改项目创建、提交、推送、Git 索引同步、模板 baseline 写入、模块注册器、LAN、MCP 策略或 AppShell。

## 测试计划

- 静态布局断言：项目区不存在“打开所选项目”和“基础分支”，新建/刷新分别位于对应输入框右侧；
- 提交布局断言：提交与推送按钮位于提交描述框右侧，四段操作范围及命令文本保持不变；
- 规则布局断言：六个规则按钮只有一个动作条，旧四个按钮字段和事件处理器不存在；
- 刷新行为：有未保存修改时覆盖保存、放弃、取消；确认后只执行一次强制刷新并原子替换表格；
- `git.rule.review` 覆盖零未决、只有建议、只有未知格式、目录候选、混合结果、缓存命中和扫描失败；
- 静态断言 `git.rule.gaps/suggest` 不再注册，`git.rule.review` 为只读且 Data 能跨 Service/Web 正确反序列化；
- `RepositoryTargets`、`GitRules`、`PromptGovernance` 和 `Docking` 定向 Smoke 全绿；
- 项目操作页在常规、恢复后窄窗和高 DPI 下无重叠，单排动作条可横向滚动；
- 日常阶段执行 Contracts、Debug 构建和定向 Smoke 并生成开发候选；Release、完整 22 次 Smoke、六份 Help、
  正式包、部署和回滚留到发布候选阶段；
- 不执行开机自启动、真实推送、真实 Git 写入、UAC 或双机 LAN 测试。
