# V2.2.0-M3 · Codex 飞轮第一圈操作手册

> 读者：Codex(经 onehistory MCP 连接宿主的 AI 客户端)
> 目标：亲手转完自扩展飞轮第一圈(A220-9)与第二圈迭代(A220-11)——
> **建项目 → 写工具 → 构建 → tool_sync 入库 → 你自己经 MCP 调用它**。
> 你既是施工者也是验收对象:最后一跳必须是你的原生 MCP 工具调用。

---

## 0. 开工前确认(每项不满足就停下来报告)

1. 宿主已从**资源管理器**启动部署版(`C:\OneHistory\OneHistory-Push\OneHistoryStudio\`),
   不得从带文件沙盒的终端启动(会看到虚拟文件层,V2.0 排障记录)。
2. MCP 调用 `mcp_status` 不可用(mcp.* 硬排除)——改用 `tool_scan` 探活:能返回即服务正常。
3. 你的任务里应能看到 `mcp__onehistory__tool_scan / tool_sync / tool_list / proj_create` 等工具;
   看不到 tool_* = 宿主是旧版,停下报告。
4. 当前策略应为 standard(能看到 proj_create 即是)。

## 1. 第一圈:五跳全链路(A220-9)

### 跳 1 · 盘点起点(MCP)

调用 `tool_scan`——生产库当前应为「共发现 0 份工具清单」。记录输出。

### 跳 2 · 建工具项目(MCP)

调用 `proj_create`,name 建议 `2026-019-Studio工具箱`(用户如有编号偏好以用户为准)。
成功后 worktree 位于 `C:\OneHistory\OneHistory-Projects\2026-019-Studio工具箱\`。

### 跳 3 · 写工具源码(本地文件)

在 worktree 内建 `b-Code-ToolKit\` 放四个文件。第一个工具建议**无副作用的实用件**
(哈希/GUID/时间戳),以下模板可直接用,业务方法你可自行增改:

`ToolKit.csproj`:
```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <GenerateDocumentationFile>true</GenerateDocumentationFile>
    <NoWarn>$(NoWarn);CS1591</NoWarn>
  </PropertyGroup>
</Project>
```

`ModuleInfoBase.cs`——契约副本,**namespace 必须是 BaseVariable,一字不改**
(从 `b-Code-OneHistoryStudio\samples\DemoModule\ModuleInfoBase.cs` 原样复制)。

`ModuleInfo.cs`:
```csharp
using BaseVariable;
namespace ToolKit;
public class ModuleInfo : ModuleInfoBase
{
    public override string ModuleName => "ToolKit";
    public override string Description => "Studio 工具箱:哈希/GUID/时间戳(飞轮第一圈产物)";
    public override string Version => "1.0.0";
    public override Type? MainClassType => typeof(Kit);
}
```

`Kit.cs`(XML 注释会成为指令帮助与 MCP 提示词,认真写):
```csharp
using System.Security.Cryptography;
using System.Text;
namespace ToolKit;
public class Kit
{
    /// <summary>计算文本的 SHA-256(十六进制大写)</summary>
    /// <param name="text">要哈希的文本</param>
    public string Sha256(string text)
        => Convert.ToHexString(SHA256.HashData(Encoding.UTF8.GetBytes(text)));

    /// <summary>生成一个新 GUID</summary>
    public string NewGuid() => Guid.NewGuid().ToString();

    /// <summary>当前本地时间与 Unix 秒</summary>
    public static object Now() => new { local = DateTime.Now, unix = DateTimeOffset.Now.ToUnixTimeSeconds() };
}
```

### 跳 4 · 构建(本地 CLI)

```powershell
$env:DOTNET_EnableWriteXorExecute='0'
dotnet build "C:\OneHistory\OneHistory-Projects\2026-019-Studio工具箱\b-Code-ToolKit" -c Release
```
必须 0 error;产物在 `b-Code-ToolKit\bin\Release\net8.0\`(ToolKit.dll + ToolKit.xml)。

### 跳 5 · 清单声明(本地文件)

建 `z-Module\module.manifest.json`(z 级元文件夹,路径一律 worktree 内相对):
```json
{
  "name": "ToolKit",
  "version": "1.0.0",
  "description": "Studio 工具箱:哈希/GUID/时间戳",
  "artifact": "b-Code-ToolKit/bin/Release/net8.0/ToolKit.dll",
  "mcpExposure": "standard"
}
```

### 跳 6 · 入库(MCP)

1. `tool_scan` → 应见 `ToolKit 1.0.0 [未同步]`;有报错先修清单再来。
2. `tool_sync`(arguments: `{"name":"ToolKit"}`) → 「✓ 入槽 Modules\ToolKit\」。
3. `tool_list` → ToolKit [在位],记录 SHA-256 前缀。

### 跳 7 · 关键一跳:你自己调用它(MCP,**新任务**)

工具表是任务级快照——**结束当前任务,新开一个任务**,然后:
1. 确认工具表出现 `mcp__onehistory__ToolKit_Sha256 / ToolKit_NewGuid / ToolKit_Now`。
2. 原生调用 `ToolKit_Sha256`,arguments `{"text":"OneHistory"}`;
   **期望精确值**(可对答案,模板代码未改动时):
   `49F22E35BC291FB8EF82016331A54BFEBD69D9B6779F2E45CC297EDD990CD86B`。
3. 调用 `ToolKit_Now`,确认结构化 JSON 返回。

### 跳 8 · 收尾入库(MCP)

`proj_commit`(arguments: `{"name":"2026-019-Studio工具箱","msg":"飞轮第一圈:ToolKit v1.0.0"}`)
——工具项目自身进裸仓库,来源可追。

## 2. 第二圈:迭代(A220-11)

1. 改 `Kit.cs`:给 Sha256 增加一个可选参数 `upper`(bool,默认 true,false 输出小写)——
   或你认为更有用的小改动;版本改 `1.0.1`(ModuleInfo 与 manifest 同步改)。
2. 重新 `dotnet build -c Release`。
3. (MCP)`tool_scan` → ToolKit 应显示 `[已过期]`。
4. (MCP)`tool_sync name=ToolKit` → 重新入槽。
5. **再开新任务**,调用改动后的工具,确认新行为与新提示词生效。
6. `proj_commit` 第二次提交(msg=`飞轮第二圈:ToolKit v1.0.1`)。

## 3. 纪律与边界

- **不动**宿主与 AppShell 源码、不手工往 `%AppData%\OneHistoryStudio\Modules` 放文件
  (那是 tool_sync 的地盘);工具产物永不进 OneHistory-Push 部署区。
- 危险指令(proj_delete / tool_remove / commitall 等)被 MCP 拒绝属**正常安全行为**,不要绕。
- manifest 校验错误会在 tool_scan 里逐条标注(路径越界/重名/缺字段),按提示修。
- 宿主控制台能看到你每次调用的回显(`[cmd:MCP:codex]`),排障先看那里与 mcp_history 表。
- 全程记录各跳的实际输出,完成后把记录交给用户(或直接写入
  `docs\02-项目验收单.md` V220 章节 A220-9 / A220-11 两条,格式照既有条目)。
