# V3.0 OneHistoryStudio 整体模块化迁移

> 日期：2026-08-07
> 状态：AppShell 3.1.7 正式宿主已发布；OHS 3.0.0-preview.1 已完成业务页面模块候选并部署到 AppShell 自有 Modules 目录。业务服务组合尚未迁移。

## 目标

V3.0 将 OneHistoryStudio 从“自带 UI、ServiceHost 和前后端代理的独立 EXE”迁移为 AppShell 的一个完整业务模块。
AppShell 成为唯一桌面宿主和后台服务宿主；OHS 最终只交付可被模块注册器装载的业务 DLL，不再交付
`OneHistoryStudio.exe`、第二套 `ServiceHost`、第二套 `ShellWindow`、第二套模块注册器或第二套 MCP/Web 网关。

公开命令名称、参数、端口、数据目录、Git 行为、LAN 配对协议和 MCP/Web 协议保持不变。本迁移不重写业务，也不复制或修改 AppShell 源码。

## 当前事实

### OHS 2.9.1

- `b-Code-Studio/Studio.csproj` 当前仍是 `WinExe`；业务服务、WPF 页面、LAN、Git、命令注册和旧服务组合仍在同一产品工程内。
- `Program.cs` 仍承载 UI、`--service-host`、`--generate-manual` 和 LAN 安装入口；`App.xaml.cs` 仍承载窗口表、前端连接和远程命令代理。
- `Service/StudioServiceCompositionFactory.cs` 仍是旧 EXE 的兼容宿主适配层；V3 分支已经把 OHS 业务组合抽成可注入边界，但尚未删除旧宿主。
- 新增 `b-Code-Studio/Module/OneHistoryStudio.Module.csproj`，只编译初步模块骨架，不改变旧产品工程。

### AppShell 3.1.7 正式消费合同

唯一正式宿主快照为：

`C:\OneHistory\OneHistory-Projects\2026-023-AppShell\z-Package-AppShell`

- 正式入口：`z-Package-AppShell/host/AppShell.exe`（快照内相对路径为 `host/AppShell.exe`）。
- 正式快照身份由 `manifest.json` 与 `SHA256SUMS` 校验。
- manifest 权威字段：`version=3.1.7`、`sourceCommit=d50234589ccd420eb5b26e18b4894c22a347b5e8`、`sourceDirty=false`。
- 3.1.7 正式部署交付完整宿主快照，不提供当前 NuGet feed；兼容嵌入消费方如需框架包，必须使用单独批准的同版本包源。
- 3.1.7 已提供 `ModuleHost`、隔离且可回收的模块槽、模块命令注册与命令来源投影、模块卸载/热重载、`IUiModule`、`IShellUiAware`、`IShellUiRegistrar`、唯一模块管理页和 `module.*` 管理命令。
- 模块能力由消费方显式开关控制：`EnableModules` 启用模块发现、命令注册和管理命令，`EnableUiModules` 仅启用 UI 模块装载；两者均不改变 AppShell 的默认宿主边界。
- 宿主模块目录为应用自己的 `%APPDATA%\\AppShell\\Modules`；无窗服务使用 `%APPDATA%\\AppShell\\service\\Modules`。AppShell 不扫描全局 `OneHistory-Projects\\*\\z-*`。

## 业务页面模块候选

初步候选版本为 `3.0.0-preview.1`，正式构建产物为：

- `OneHistoryStudio.dll`；
- `OneHistoryStudio.xml`；
- `module.manifest.json`；
- `SHA256SUMS`。

候选模块提供：

- 兼容的 `BaseVariable.ModuleInfoBase`，模块名 `OneHistoryStudio`；
- 只读命令 `OneHistoryStudio.Status`，用于证明后台模块目录已经被宿主发现；
- `IUiModule + IShellUiAware`，注册 `overview`、`tree`、`meta`、`projops`、`history` 五个稳定窗口 ID；
- 直接复用项目总览、继承树、Meta 文件、项目操作和分支历史五个真实 WPF 页面，不再提供 OneHistoryStudio 占位主界面；
- `DestroyUi` 逆序释放全部窗口注册，不创建第二个 Shell 或顶层 OHS 进程。

候选模块仍未获得 AppShell 3.1.7 宿主 `CommandBus` 注入合同，因此页面命令访问器暂不接入业务服务；当前验收范围是页面编译、注册、停靠、卸载和宿主加载，不是 V3.0 正式发布。

## 责任边界

| 责任 | AppShell 宿主 | OneHistoryStudio 模块 |
|---|---|---|
| 进程与窗口 | `AppShell.exe`、单实例、`ShellWindow`、停靠布局、控制台和标准窗口 | 注册 OHS 业务窗口及内容工厂 |
| 后台服务 | `ServiceComposition`、`ServiceHost` 生命周期、服务事件循环和统一释放 | 提供 OHS 业务组合及命令注册入口 |
| 命令总线 | `CommandRegistry`、`CommandBus`、确认、命令来源和冲突门禁 | 注册 OHS 业务 `CommandDescriptor`，保持现有命令语义 |
| MCP/Web | 网关、监听、鉴权、确认、审计、前后端中继 | 声明 OHS 命令暴露策略和 Web/LAN 业务扩展需求 |
| 模块运行时 | manifest 解析、依赖/冲突、模块槽、加载、卸载、热重载和管理页 | 提供模块 manifest、DLL、XML 和面板声明 |
| 项目资料 | 不理解项目仓库语义 | 管理项目 worktree、Git 规则、发布区和项目级资料 |

## 模块元数据责任边界

AppShell 负责模块运行时元数据：模块 manifest 的发现与校验、版本和入口 DLL、命令域冲突、依赖、加载状态、模块槽、生命周期和热重载。

OHS 继续负责项目库元数据：worktree 下的 `z-*` 元文件夹、Git 文件规则、模板基线、`b-Publish`、`z-Package` 以及项目文档和历史。
发布管道把审核通过的 OHS 模块快照从 OHS `z-Package` 同步到 AppShell 的两个宿主 Modules 目录；AppShell 只消费已同步的正式模块目录。

OHS 不再复制 `ModuleHost`、模块管理页面或第二套 manifest 运行时。`ToolSyncService` 后续只保留项目清单治理，宿主模块安装、加载和热重载归 AppShell 或独立部署管道所有。

## 尚未具备的宿主合同

AppShell 3.1.7 已能承载宿主级 `ServiceComposition` 和 `ServiceHost`，但还没有为 OHS 这类完整业务模块冻结以下公开合同：

- 服务模块注册、配置、释放和热重载生命周期；
- 模块专属数据根，同时保持 `%APPDATA%\\OneHistoryStudio` 数据兼容；
- 外部模块向宿主注册复杂 `CommandDescriptor`、确认通道和命令来源的稳定入口；
- OHS Web/LAN 健康检查、发现、配对和服务扩展的宿主注册接口。

`IServiceModule`、`IModuleContext`、`IModuleWebRegistration` 等名称仅表示待设计能力，不是 AppShell 3.1.7 已发布 API。OHS 施工不得提前引用这些假定接口。

## OHS 模块内部结构

OHS 对模块注册器只发布一个模块，源码内部按功能内聚分层：

- 模块身份、宿主组合入口、版本和释放合同；
- 项目、Git 规则、分支历史、历史记录、格式库存和连接业务服务；
- 现有 `CommandDescriptor`、参数、确认、DTO 和反序列化适配；
- 概览、继承树、Meta、项目操作、历史和连接页面。

模块不得创建 `ServiceHost`、`McpGateway`、`WebGateway`、`ModuleHost` 或 `ShellWindow` 实例，也不得直接依赖 AppShell 内部 AvalonDock 类型。

## 正式发布形态

V3.0 OHS `z-Package` 改为模块消费区，只保存最新经过验证的 OHS 模块快照。正式产物为模块 DLL、XML、`module.manifest.json` 和 checksum。
不进入 OHS 模块正式包：AppShell 宿主 DLL、runtimeconfig/deps、旧 OHS EXE、旧 Service 入口、临时构建目录和测试证据。
AppShell 运行包始终从 023 的 `z-Package-AppShell` 消费。

## 迁移顺序

1. 固定消费 AppShell 3.1.7 Z 快照，核对 manifest、文件清单和 SHA-256；不引用 AppShell 工作树。
2. 保留当前 `StudioBusinessCompositionFactory` 作为可注入业务边界，完成服务模块合同后再迁移业务服务。
3. 把现有业务窗口迁入 `IUiModule`，删除第二套 Shell 装配，确认默认停靠和卸载后无残留窗口。
4. 将 OHS 业务组合接入宿主服务模块上下文，删除 OHS 自建 ServiceHost、MCP/Web 生命周期和前端代理。
5. 使用原 `%APPDATA%\\OneHistoryStudio` 数据根，验证数据库、设置、设备 token、LAN 指纹、布局和 Git 项目原地复用。
6. 执行模块合同、宿主装载/卸载/热重载、OHS 定向 Smoke 和前后端分离验证；候选只进入 `b-Publish/candidate`。
7. 核对 module manifest、SHA-256、OHS 模块版本和 AppShell 3.1.7 宿主版本后，更新 OHS `z-Package`。
8. 部署管道把 OHS 模块同步到 AppShell 两个 `Modules` 槽，人工验收后停止旧 OHS EXE；保留旧数据库和回滚包。

## 测试与门禁

- 页面候选：Release 模块构建、manifest/XML/checksum、AppShell 服务端发现 1 条只读命令、前端发现 UI 模块并完成五个业务窗口注册，且不存在占位主界面。
- 正式候选：服务模块注册/释放、复杂命令、原数据根、OHS 六个业务窗口、完整 Smoke、Help、正式包、部署和回滚。
- 正式包静态门禁：只有模块 DLL、XML、manifest 和 checksum，不含 OHS EXE、独立 Service EXE 或 AppShell 运行库复制品。
- 不执行开机自启动测试；真实 UAC、防火墙、双机 LAN 和用户数据升级留作发布候选人工验收。

## 不变项与非目标

- 不修改公开命令名称、参数、数据库 schema、Git 提交/推送语义、LAN 配对协议和 MCP/Web 协议。
- 不在 OHS 中保留一层“薄 ServiceHost”兼容入口；V3 完成后唯一宿主是 AppShell。
- 不把 AppShell 工作树当作依赖；OHS 只消费正式 3.1.7 Z 快照。
- 本阶段不修改 OHS 版本号为正式 V3.0，不发布正式 OHS 包，不修改 AppShell 源码。

## 验收结论

当前仅证明“AppShell 3.1.7 能在自己的前端和服务 Modules 目录发现并装载 OHS 初步模块”。
只有同时满足服务模块合同正式发布、OHS 业务 DLL 可在服务/UI 两侧完整装载、原数据和命令行为不变，以及 OHS `z-Package` 不含任何 OHS EXE，才允许将 V3.0 标记为正式完成。
