# OneHistoryStudio 源码治理与项目边界规划

> 文档性质：代码审查后的工程治理规划  
> 日期：2026-07-15  
> 适用范围：OneHistoryStudio 自身源码、受管 Project 工作树、裸仓库  
> 状态：M1.5 已落实 Git 参数、repair/Meta 边界与基础 ignore；控制界面和位置指令待排期

---

## 1. 背景与判定

OneHistoryStudio 本身就是项目管理与 Git 可视化工具，因此源码治理不能只依赖仓库外部人工维护。
它既要管理其他项目的 `.gitignore`，也必须能够识别和治理自身源码中的 IDE 缓存、编译输出、
发布产物等文件。

当前仓库中 `.vs`、`bin`、`obj`、`Publish` 等生成内容占受控文件的大多数，导致一次小范围源码
修改产生大量二进制和缓存变化。该问题会直接影响状态展示、提交审查、仓库体积和工具自身的
可信度，优先级定为 **P0**。

同时，现有 `proj.*` 对“裸仓库在哪里、Project 根目录在哪里、允许操作哪些路径”的约束主要
依赖配置约定，尚未形成统一的路径边界模型。尤其 `proj.repair` 会依据 Git 返回的 worktree 路径
递归删除目录，必须在继续扩展自动化能力前补齐安全边界。

## 2. `.gitignore` 手动控制界面

### 2.1 目标

新增一个可视化的 Ignore 管理窗口，所有写操作仍先注册为命令，再由 UI 调用命令总线。窗口既可
选择任意已登记 Project，也可选择 OneHistoryStudio 自身所在 Project。

建议命令域：

| 指令 | 行为 |
|---|---|
| `proj.ignore.show name=` | 显示目标项目 `.gitignore`、规则来源及匹配统计 |
| `proj.ignore.check name= path=` | 解释某路径是否被忽略，等价复用 `git check-ignore -v` |
| `proj.ignore.add name= pattern=` | 添加一条规则，去重后保存 |
| `proj.ignore.remove name= pattern=` | 删除精确匹配的规则 |
| `proj.ignore.apply name= preset=` | 应用 `dotnet`、`visualstudio`、`publish` 等预设规则 |
| `proj.ignore.scan name=` | 扫描已跟踪的生成文件并给出治理报告，不直接取消跟踪 |

界面至少包含：Project 选择、规则文本编辑、预设规则选择、规则验证、已跟踪但应忽略文件列表、
保存按钮。保存前展示 diff；不得在保存 `.gitignore` 时自动执行 `git rm --cached`。

### 2.2 自身源码治理

OneHistoryStudio 必须通过与其他 Project 相同的命令和界面管理自身，禁止额外写一套特殊逻辑。
程序应根据当前可执行文件位置和 worktree 清单识别自身 Project；部署版运行时仍应指向源码
worktree，而不是把部署目录误认为源码仓库。

推荐的基础规则：

```gitignore
.vs/
**/bin/
**/obj/
TestResults/
*.user
*.suo
```

`Publish/` 是否忽略必须由项目策略决定：若发布产物作为正式制品单独交付，应忽略并由发布流程
生成；若确实选择把便携版纳入 Git，则应在界面中明确标记为“受控制品目录”，避免被扫描器当成
普通源码变化。

### 2.3 已跟踪文件的处理

`.gitignore` 只影响未跟踪文件，不会自动移除已经进入索引的 `.vs/bin/obj/Publish`。治理流程应
分成两步：

1. 编辑、验证并提交 `.gitignore`。
2. 单独执行“从索引取消跟踪但保留本地文件”，展示待处理清单并要求人工确认。

第二步属于高风险操作，未来可设计 `proj.ignore.untrack`，必须带 `ConfirmPrompt`，默认不得通过
MCP 调用。首版也可以只输出建议命令，由用户在宿主控制台人工执行。

## 3. Project 与裸仓库位置控制

### 3.1 统一位置模型

建议引入一份结构化位置配置，而不是让各命令自行拼接字符串：

| 字段 | 含义 |
|---|---|
| `bareRepo` | 裸仓库的规范化绝对路径 |
| `projectRoot` | 受管 Project/worktree 的唯一根目录 |
| `selfProject` | OneHistoryStudio 自身源码 worktree，可自动发现后人工确认 |
| `allowedRoots` | 允许只读发现的附加根目录；默认空 |
| `allowExternalWorktrees` | 是否允许登记根目录外 worktree，默认 `false` |

建议增加 `project.location` 命令域：

| 指令 | 行为 |
|---|---|
| `project.location.show` | 显示当前裸仓库、Project 根、自身源码及边界状态 |
| `project.location.validate` | 检查路径存在性、Git 类型、包含关系、重复与越界 worktree |
| `project.location.set root= bare=` | 设置新位置；保存前完整验证 |
| `project.location.discover` | 只读发现候选位置，不自动写配置 |
| `project.location.external` | 列出所有根目录外 worktree 及其处理建议 |

### 3.2 强制边界规则

所有涉及创建、移动、删除、修复和打开目录的命令必须共用同一个路径守卫：

1. 使用 `Path.GetFullPath` 规范化路径，并处理尾部分隔符与大小写。
2. 裸仓库不得位于会被 `proj.repair` 清理的 Project 根目录内部。
3. 创建 worktree 的目标必须是 `projectRoot` 的直接子目录。
4. 删除或修复只能处理 `projectRoot` 内已登记的直接子目录。
5. Git 返回根目录外的 worktree 时，列为异常并拒绝破坏性批处理；不得“警告后继续删除”。
6. 符号链接、junction/reparse point 必须识别；破坏性操作不得借其逃逸到允许根之外。
7. Project 根、裸仓库根、磁盘根目录以及 OneHistoryStudio 部署目录均不得成为递归删除目标。

`proj.repair` 在路径验证全部通过前不得删除任何目录，避免出现“前几个已删除、后面才发现越界”
的半完成状态。建议先生成修复计划，人工确认计划后再执行。

### 3.3 Meta 文件边界

`proj.metaopen path=` 应仅接受 `proj.metalist` 可枚举到的 Project 一级 `z/Z` 文件夹。完整路径模式
也必须验证其父目录是已登记 worktree，不能只检查最后一级目录名是否以 `z/Z` 开头。

## 4. Git 进程参数治理

`GitRunner` 当前接收拼接后的单个参数字符串。提交信息、配置分支名或路径中出现引号和反斜杠时，
可能被 Windows 进程参数解析器重新解释。

后续应把接口改为结构化参数，例如 `RunAsync(string gitDir, params string[] args)`，内部使用
`ProcessStartInfo.ArgumentList` 逐项添加 `-C`、工作目录和 Git 参数。调用方不得自行添加包围引号
或做命令行转义。该改造应覆盖 commit message、分支名、worktree 路径和 LFS 文件路径。

## 5. 自动化测试安排

自动化测试当前不作为交付阻塞项，后续集中补齐。优先覆盖：

- 路径规范化、根目录包含判定、junction/越界拒绝。
- `proj.repair` 计划生成，保证出现任何越界项时零删除。
- `.gitignore` 规则增删、去重、预设合并和 `git check-ignore` 结果解析。
- GitRunner 对空格、中文、引号、尾部反斜杠参数的原样传递。
- MCP Schema 与参数反向组装。

测试必须使用临时裸仓库和临时 worktree，不得对生产 Project 根执行删除或修复。

## 6. 建议实施顺序

| 顺序 | 工作 | 优先级 | 出口 |
|---|---|---|---|
| 1 | 给 `proj.repair` 增加路径守卫和执行前计划 | P0 | 越界 worktree 时零删除并明确拒绝 |
| 2 | 建立自身可用的 `.gitignore` 命令与控制界面 | P0 | 可查看、验证、编辑自身及任意 Project 规则 |
| 3 | 清理已跟踪生成文件 | P0 | 日常源码修改不再产生 IDE/编译缓存 diff |
| 4 | 增加 `project.location.*` 位置控制 | P1 | 裸仓库与 Project 根可验证、可迁移、可审计 |
| 5 | GitRunner 改用结构化参数 | P1 | 特殊字符参数不失真、不被重新解释 |
| 6 | 收紧 `proj.metaopen` 路径范围 | P1 | 只能打开已登记 Project 的一级 Meta 文件夹 |
| 7 | 补自动化测试 | P2 | 核心边界逻辑可重复回归 |

## 7. 验收原则

- OneHistoryStudio 能管理自身 `.gitignore`，且与管理其他 Project 走同一套命令和 UI。
- Ignore 扫描能区分“已忽略”“未跟踪”“已跟踪但符合忽略规则”三种状态。
- 任何根目录外 worktree 都不会被 `proj.repair`、删除或批处理命令修改。
- 修改位置配置前展示旧值、新值、验证结果及受影响 worktree 数量。
- 所有破坏性动作经命令总线 `ConfirmPrompt`，并保留操作记录。
- MCP 的 readonly/standard 策略不得绕过本文件定义的路径守卫。
