# V2.2.0-M4 · 宿主确认中继交互验收(A220-13 点击两态)

> 读者:Codex(发起方)+ 用户(宿主端点击裁决方)
> 目标:验证 `mcp.confirm=host` 下危险指令的「人工批准→执行」与「人工拒绝」两态。
> 自动化已覆盖:deny 档拒绝(A220-12)、超时拒绝(A220-13 超时态)、--yes 不放行(A220-14)。
> 本手册只补两个需真人点击的状态。

## 0. 前置(用户)

1. 从资源管理器启动部署版(`C:\OneHistory\OneHistory-Push\OneHistoryStudio\`,应为 2.2.0)。
2. 部署时已置 `mcp.confirm=host` / `mcp.confirmtimeout=60` / `mcp.policy=standard`;
   在控制台执行 `mcp.status` 确认「危险指令: mcp.confirm = host」。
3. 准备一个**可安全删除的沙盒目标**——不要用真实项目。在控制台执行(生产库内建一个即弃分支):
   `proj.create name=9999-921-中继验收`(它会成为一个真实但一次性的 worktree)。

## 1. 态一:人工批准 → 执行(A220-13 approve)

1. (Codex,新任务)确认工具表含 `mcp__onehistory__proj_delete`(host 档下危险指令可见,
   描述带「⚠ 危险操作:调用会请求宿主端人工确认」)。
2. (Codex)原生调用 `proj_delete`,arguments `{"name":"9999-921-中继验收"}`。
3. (用户)宿主屏幕弹出「MCP 远程请求 · 需要确认」框,标题含客户端名,正文是 proj.delete 的
   完整警告文案 + 等价指令 + 倒计时。**点「允许执行」**。
4. (Codex)应收到成功结果(worktree 与分支已删除);**不应出现第二个确认框**
   (预批准域已使总线不再二次弹框)。
5. (用户)控制台 `db.query table=mcp_history order="id desc" limit=3` 应见一行
   result=「远程确认通过·成功」。

## 2. 态二:人工拒绝(A220-13 reject)

1. (用户)再建一个即弃目标:`proj.create name=9999-922-中继拒绝`。
2. (Codex,可同任务)再次 `proj_delete`,arguments `{"name":"9999-922-中继拒绝"}`。
3. (用户)弹框出现,**点「拒绝」**。
4. (Codex)应收到 isError=true、文本「宿主已拒绝该远程请求(人工点否)」;
   worktree 仍在(未删除)。
5. (用户)mcp_history 应见 result=「远程拒绝」;控制台 `proj.list` 确认 9999-922 仍在,
   随后手动 `proj.delete name=9999-922-中继拒绝` 清理即弃目标。

## 3. 通过判据

- [ ] 态一:批准后指令执行成功、**无二次弹框**、mcp_history=远程确认通过·成功
- [ ] 态二:拒绝后指令未执行、Codex 收到拒绝文本、mcp_history=远程拒绝
- [ ] 两态弹框均标注 MCP 客户端名与倒计时
- [ ] 清理两个即弃沙盒目标(9999-921 / 9999-922)

## 4. 边界提醒

- 中继只在 `mcp.confirm=host` 且 `mcp.policy=standard` 时生效;readonly 档不受理危险指令。
- 想恢复"绝不远程执行危险指令"的最保守姿态:`app.set key=mcp.confirm value=deny`。
- `--yes` 自动确认对 MCP 危险调用**永不生效**——即使宿主以 --yes 启动,远程危险请求仍弹框。
- 全程记录交给用户签字到 `docs\02-项目验收单.md` A220-13 两态。
