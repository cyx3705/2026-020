## 1. 版本目标

V2.1.3 分为两个独立里程碑：

1. **M1 Git 属性规则调试器**：诊断 `.gitattributes`、Git LFS 命中、索引状态和历史体积问题；
2. **M2 命令集管理页**：把 V2.1.1 的“MCP 工具”页升级为程序全部指令的统一观察入口，同时保留 MCP 映射和提示词治理。

二者的共同目标是让 OneHistory 不只会执行操作，还能解释“当前规则和能力为什么是这样”。

## 2. M1：Git 属性规则调试器

### 2.1 已确认的模板现状

对 `0000-000-Template/.gitattributes` 的本机实测结果：

- `Logo.png` 命中 `filter=lfs / diff=lfs / merge=lfs / -text`；
- `BOM表.xlsx`、`_model.prt`、`零件.SLDPRT` 未命中属性；
- `\#`、`常见视频格式`、`Pro`、`工程文件`、`Premiere` 被 Git 当作文件匹配模式，而不是注释；
- 当前仓库 pack 约 2.32 GiB，而 `git lfs ls-files` 识别的 LFS 文件很少；
- 全部项目共享一个裸仓库，历史迁移会同时影响项目继承图和远端提交 ID。

因此首要目标是诊断和安全编辑，不自动执行历史重写。

### 2.2 指令域

| 指令 | 行为 | 风险 |
|---|---|---|
| `attr.rules name=` | 列出规则、来源文件、属性和可疑状态 | 只读 |
| `attr.check name= path=` | 调用 `git check-attr -a -- path` 显示最终属性 | 只读 |
| `attr.scan name= [minmb=]` | 扫描当前工作树、索引和 LFS 指针状态 | 只读 |
| `attr.validate name=` | 查空规则、可疑标题、不完整 LFS 组合和重复规则 | 只读 |
| `attr.history name= [all=false]` | 报告对象库、LFS和历史大文件，不修改历史 | 只读、长任务 |
| `attr.add name= pattern= preset=` | 添加规则，保存前给出 diff | 本地确认 |
| `attr.remove name= pattern=` | 精确删除规则，保存前给出 diff | 本地确认 |
| `attr.preset name= preset=` | 合并预设规则，去重并给出 diff | 本地确认 |
| `attr.renormalize name=` | 执行 `git add --renormalize .` | 高风险、本地确认 |

不提供日常指令直接包装 `git lfs migrate import`。历史迁移必须单独生成迁移报告、备份裸仓库、确认受影响分支，再由人工专项执行。

### 2.3 诊断真值与解析边界

最终属性必须以 Git 原生命令为准：

```text
git check-attr -a -- <path>
git lfs track
git lfs ls-files
git lfs migrate info
git count-objects -vH
```

自有解析器只负责：

- 保留空行和注释；
- 定位规则所在文件与行号；
- 识别可疑文本、重复和不完整属性组合；
- 生成保存 diff；
- 计算候选规则命中数。

自有解析结果不得替代 `git check-attr` 的最终生效结果。Git 参数全部经结构化 `GitRunner` 传递。

### 2.4 扫描分类

| 状态 | 判定 |
|---|---|
| 正常 LFS | 命中 LFS 规则，索引内容是 LFS 指针 |
| 命中但未转换 | 命中规则，但索引仍是普通 Git blob |
| 大文件未覆盖 | 达到阈值但没有 LFS 属性 |
| 空规则 | 当前扫描范围内命中数为 0 |
| 可疑规则 | 疑似将标题、说明文字写成了匹配模式 |
| 不完整 LFS | `filter/diff/merge/-text` 组合不完整 |
| 历史占用 | 当前树已修复，但旧提交仍保存大 blob |

### 2.5 页面设计

新增 `Git 属性` 工具窗口，包含：

- Project 选择、扫描、历史分析；
- 规则表：规则、来源、行号、命中数、属性、状态；
- 文件测试：路径、最终属性、文件大小、LFS 指针状态；
- 问题列表：严重度、原因、建议；
- 修改预览：原内容、新内容、diff、保存或放弃；
- 预设选择：机械、NX、SolidWorks、Solid Edge、二维、Altium、Office、媒体；
- `renormalize` 与历史迁移分离，禁止保存规则时顺带执行。

页面所有动作经 `attr.*` 指令进入总线。指令名遵守框架“域.动作”两段式语法。MCP 首版只开放 check、rules、scan、validate 和 history 报告；修改规则只允许 AI 提案或本地人工执行。

## 3. M2：命令集管理页

### 3.1 升级原因

V2.1.1 页面以 `mcp.schema` 为数据源，只能看到“注册表减去硬排除”的 MCP 工具。程序实际还有 `mcp.*`、`debug.*`、`app.exit` 等本地指令，用户无法在同一页确认程序到底注册了多少能力。

V2.1.3 将页面语义改为 **命令集**：上游真值是 `CommandRegistry.All()`，MCP 工具只是每条指令的一种投影。

### 3.2 兼容判定

- 页面显示标题改为“命令集”；
- 为避免破坏已有布局，V2.1.3 暂保留窗口内部 ID `mcp` 和 `win.show name=mcp`；
- 文档和菜单统一称“命令集”；
- 后续若迁移为 ID `commands`，必须先提供布局迁移或兼容别名，不在本版强改。

### 3.3 新指令

| 指令 | 行为 |
|---|---|
| `command.list [domain=] [mcp=all/visible/hidden] [filter=]` | 结构化列出全部注册指令 |
| `command.show name=` | 返回 Summary、Example、参数、危险位、来源和 MCP 映射 |
| `command.domains` | 列出指令域及数量 |

`help` 继续作为人类可读帮助的唯一基础入口；`command.*` 为页面和 MCP 提供结构化数据，不复制另一套手写说明。

### 3.4 命令模型

页面每行至少包含：

```text
CommandName, Domain, Summary, Example, ParameterCount,
Source(framework/app/module), Dangerous, RequiresUiThread,
McpToolName, McpState(visible/readonly/standard/hidden),
Customized, CurrentRevision
```

来源判定必须稳定：框架内置、OneHistory App、热加载模块分别标记。模块下线后页面即时刷新，历史提示词和事故记录不物理删除。

### 3.5 页面布局

左侧命令表支持按名称、域、说明搜索，并按以下条件过滤：

- 全部 / MCP 可见 / MCP 隐藏；
- 只读可用 / standard 可用 / 危险拒绝；
- 框架 / App / 模块；
- 有自定义提示词 / 有待审核提案 / 有事故记录。

右侧详情分为：

1. **Help**：Summary、参数、默认值、允许值、示例；
2. **MCP**：工具名、JSON Schema、策略可见性、硬排除原因；
3. **提示词**：默认、生效、修订、提案和 diff；
4. **历史**：相关勘误、事故和调用记录。

按钮包括：

- 查看 help（执行 `help <command>`）；
- 查看 MCP 形态（执行 `mcp.schema name=<command>`，硬排除项说明原因）；
- 复制示例；
- 提交提示词修改；
- MCP 服务状态；
- 刷新命令集。

### 3.6 MCP 可见性表达

页面必须分清：

- 注册表总指令数；
- 被硬排除的指令数及原因；
- readonly 策略可见数；
- standard 策略可见数；
- 带 `ConfirmPrompt`、远程始终拒绝的危险指令数；
- 模块动态注册的指令数。

不能再把“MCP 工具数量”等同于“程序指令数量”。

## 4. 实施顺序

| 节点 | 工作 | 出口 |
|---|---|---|
| M1.1 | `GitAttributesService`、`attr.*` 只读指令、扫描模型 | 能解释单文件属性和项目问题 |
| M1.2 | 安全编辑、diff、预设、页面 | 能修正规则但不隐式改索引或历史 |
| M1.3 | LFS/对象库报告和 MCP 只读暴露 | AI 能诊断并提出方案 |
| M2.1 | `command.*` 结构化模型 | 注册表全部指令可查询 |
| M2.2 | 原 MCP 页升级为命令集页 | 全指令、MCP 映射、提示词同页查看 |
| M2.3 | 模块热重载、策略和布局回归 | 动态能力与兼容行为正确 |

## 7. 非目标

- 不在本版自动重写 Git 历史；
- 不为每种 CAD 文件实现预览或依赖解析；
- 不允许任意路径编辑 `.gitattributes`；
- 不把命令集页变成绕过确认闸口的执行器；
- 不修改 `CommandRegistry` 的单一真值地位；
- 不因页面改名破坏现有布局。
