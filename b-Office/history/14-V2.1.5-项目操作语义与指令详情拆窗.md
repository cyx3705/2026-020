# OneHistoryStudio V2.1.5 · 项目操作语义与指令详情拆窗

> 日期：2026-07-17
> 状态：已部署交付；浮动窗口人工视觉点验待补
> 前置版本：V2.1.4
> 性质：两项小范围 UI 语义修正，不扩张后端能力

## 1. 版本目标

V2.1.5 只完成两件事：

1. 修正“项目操作”窗口中“新项目名称”和“基础分支/当前项目”的职责倒置；
2. 把“命令集”窗口右侧的指令详情区域拆成独立可停靠的“指令详情”窗口。

本版不修改 Project/Git/MCP/提示词治理的业务规则，不新增平行指令，不调整数据库结构，也不重做 V2.1.4 已稳定的页面内容。

## 2. 项目操作字段语义修正

### 2.1 当前问题

V2.1.4 的项目操作页当前是：

```text
项目:      [可编辑项目下拉框]
基础分支:  [普通文本框 0000-000-Template]
```

代码把“项目”下拉框同时用于以下三种行为：

- `proj.create name=` 的新项目名称；
- `proj.open name=` 的现有项目；
- `git.rule.* name=` 的当前项目。

这混淆了“准备创建的新名称”和“已经存在的基础 Project”。真正需要从已登记项目中选择的位置应是“基础分支”，而“项目”输入框只用于给新拉出的 Project 命名。

### 2.2 冻结后的字段

| UI 字段 | 控件 | 数据来源 | 唯一职责 |
|---|---|---|---|
| 新项目名称 | 普通 `TextBox`，默认空 | 用户输入 | 只提供 `proj.create name=` |
| 基础分支 / 当前项目 | 可搜索/可编辑 `ComboBox` | `proj.list` | 创建时提供 `base=`；平时作为打开、Git 规则的当前目标 |

页面建议显示为：

```text
新项目名称:          [________________]
基础分支 / 当前项目: [0000-000-Template ▼]

[创建工作树] [打开所选项目] [刷新项目]

Git 文件规则 · 0000-000-Template
...
```

“选择项目的位置设置在基础分支上”是本项的核心约束。不得继续让新项目名称文本框承担现有项目选择职责。

### 2.3 指令映射

假设：

```text
新项目名称 = 2026-019-Demo
基础分支 / 当前项目 = 0000-000-Template
```

各操作必须固定映射为：

```text
创建工作树:
proj.create name=2026-019-Demo base=0000-000-Template

打开所选项目:
proj.open name=0000-000-Template

读取所选项目规则:
git.rule.list name=0000-000-Template
```

保存和删除规则同样只使用“基础分支 / 当前项目”的选中值：

```text
git.rule.set name=0000-000-Template ...
git.rule.remove name=0000-000-Template ...
```

禁止以下错误行为：

- 用新项目名称执行 `proj.open`；
- 用新项目名称读取或修改 Git 规则；
- 刷新项目列表时覆盖用户尚未提交的新项目名称；
- 未选择基础分支时仍允许创建、打开或编辑规则。

### 2.4 创建后的状态

创建成功后：

1. 重新通过 `proj.list` 刷新下拉列表；
2. 将新创建的 Project 选为“基础分支 / 当前项目”；
3. 清空“新项目名称”文本框；
4. 自动通过 `git.rule.list` 加载新 Project 的规则；
5. 所有指令继续使用来源 `UI` 正常回显和记录日志。

创建失败时保留两个字段原值，方便修正后重试。

## 3. 指令详情拆窗

### 3.1 当前问题

V2.1.4 的 `McpToolsView` 是内部左右分栏：

```text
命令集窗口
├─ 左侧：搜索、过滤、指令列表
└─ 右侧：指令标题与五个详情页签
   ├─ Help
   ├─ MCP
   ├─ 提示词
   ├─ 提案审核
   └─ 治理历史
```

项目总览已证明“列表”和“详情/操作”拆成独立窗口更符合现有可停靠架构。命令集也应采用同样方式，让用户独立调整列表和详情的大小、停靠位置及可见性。

### 3.2 新窗口边界

| 窗口 | ID | 保留内容 | 默认位置 |
|---|---|---|---|
| 命令集 | `mcp` | 搜索、域/MCP/来源过滤、三个治理过滤条件、指令列表、服务状态、刷新、列表状态 | 保持现有顶部标签组与布局 ID |
| 指令详情 | `commanddetail` | 指令标题以及原右侧全部五个页签和按钮 | 右侧，建议比例 `0.32`，默认可见 |

`mcp` ID 必须保持不变，以兼容 V2.1.3/V2.1.4 已保存布局。新窗口使用稳定 ID `commanddetail`，后续不得因显示标题变化而修改 ID。

命令集窗口拆分后不保留空白右栏、GridSplitter 或详情占位控件，应成为完整的单列表窗口。

### 3.3 详情内容原样迁移

以下能力整体迁入 `CommandDetailView`，不删减、不改业务语义：

- Help 摘要、参数表、示例、查看 Help、复制示例；
- MCP 可见状态、工具名、硬排除原因、JSON Input Schema；
- 提示词当前修订、应用本地修订、恢复默认、修订历史和回滚；
- 提案列表、理由/证据、差异、批准、拒绝、应用；
- 勘误和事故治理历史。

按钮继续组装现有指令并经过 `CommandBus`：

```text
command.show
help
mcp.schema
prompt.get / prompt.history / prompt.diff
mcp.pending / mcp.approve / mcp.reject / mcp.apply / mcp.revert
correction.list
incident.list
```

不得让新详情窗口直接调用 `CommandDescriptor.Handler`、数据库或 MCP 网关。

### 3.4 选择同步

两个窗口只共享“当前选中的指令名”，不共享业务数据，也不建立第二份命令目录。

实现时增加一个应用级、纯内存的 `CommandSelectionState`：

```text
McpToolsView 选择指令
        ↓ 只写 CurrentCommandName
CommandSelectionState
        ↓ Changed 事件
CommandDetailView
        ↓ 经 CommandBus 执行 command.show / prompt.* 等
```

约束：

- `CommandRegistry` 仍是全部指令的唯一真值；
- `CommandSelectionState` 只保存一个字符串和变更事件，不保存详情、Schema、提示词或数据库记录；
- 不把当前选择写入 SQLite、settings 或布局文件；
- 详情页每次加载仍通过现有指令获得结构化结果，控制台保留正常 `UI` 来源日志；
- 详情窗口晚于命令集创建时，应读取 `CurrentCommandName` 并补载当前详情；
- 模块卸载导致当前指令消失时，清空详情并显示“指令已卸载”，不得展示陈旧数据。

选择列表行只更新详情，不自动执行该业务指令。双击也不得绕过 Help 或危险确认直接运行指令。

### 3.5 窗口和布局行为

- V2.1.5 首次启动时，`commanddetail` 默认显示在右侧；
- 用户可以独立隐藏、浮动、调整比例或复位该窗口；
- `win.list/show/hide/float/dock/reset/ratio` 自动识别新窗口；
- 旧布局没有 `commanddetail` 节点时按新描述符默认位置补入，不破坏 `mcp`、`overview`、`projops` 等旧窗口；
- 隐藏详情窗口时，命令集筛选和选择仍正常；重新显示后加载最后选中的有效指令；
- 页面刷新和模块热重载后尽量保留当前选择；选择已不存在时清空。

- 不拆分五个详情页签为五个窗口；
- 不改提示词治理数据库表；
- 不改变 MCP readonly/standard、硬排除或本地确认策略；
- 不修改 `git.rule.*`、`proj.*` 的参数和行为；
- 不把新项目名称保存为全局默认；
- 不重做项目总览、模块管理或提交推送窗口；
- 不在本次文档阶段修改程序、版本号、Publish 或部署区。
