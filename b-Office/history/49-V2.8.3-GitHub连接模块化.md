# V2.8.3 GitHub 连接模块化

> 日期：2026-08-01  
> 状态：正式发布、部署与模块同步验收通过；待模块移除恢复专项验收

## 目标

V2.8.3 将 GitHub 专属能力从 OneHistoryStudio 产品中彻底迁出，交由
`2026-019-Studio工具箱` 中独立的 `GitHubConnection 1.0.0` 模块提供，并通过现有模块注册器发现、同步和加载。

迁移完成后，OHS 不再内置 GitHub 页面、服务、模型、命令、脱敏器、进程执行门面或专属测试。没有安装
GitHubConnection 模块时，OHS 必须可以独立启动并完整提供通用 Git 项目、分支、提交和推送能力，但不显示任何
GitHub 专属窗口，也不注册任何 `github.*` 命令。

## 当前事实

OHS 2.8.2 当前内置以下 GitHub 专属实现：

- `GitHubAccountModels.cs`、`GitHubAccountService.cs`、`GitHubAccountCommands.cs` 和 `GitHubRedactor.cs`；
- `GitHubAccountView.xaml` 及其后台代码；
- `GitHubAccountSuite`，以及 `DockingSuite` 对内置页面的直接构造；
- `StudioServiceCompositionFactory` 中的服务实例和七条命令注册；
- `App.xaml.cs` 中的 `github.account` 工具窗口与“GitHub 账号”菜单动作；
- `ToolProcessRunner.cs`。全库核对确认该门面除 GitHub 服务和对应测试外没有其他消费者，因此随功能一并迁出。

现行七条内置命令为 `github.status/accounts/test/login/logout/identity/remote`。其中四条修改命令依赖 OHS
命令上下文的来源检查，仅允许服务器本机 Shell。AppShell 3.0.3 的反射模块不向业务方法提供命令来源，因此不能在
不削弱安全边界的前提下原样迁移这四条命令。

## 迁移边界

### OHS 必须删除

- 删除上述 GitHub 专属生产文件和 `ToolProcessRunner.cs`；
- 删除服务装配、七条内置命令注册、内置窗口描述符和工具菜单动作；
- 删除 `GitHubAccountSuite`，从 Smoke 入口移除该套件，并从 `DockingSuite` 删除内置 GitHub 页面断言；
- 从现行使用说明、MCP 安全文档和自动生成命令手册中删除“内置 GitHub 能力”的叙述；
- OHS 正式包不得包含 `GitHubConnection.*`，模块仍由独立正式消费区和运行时模块槽负责。

### OHS 继续保留

- 通用 Git 仓库、worktree、分支、提交、推送、规则和历史能力；
- `proj.barerepo`。它描述 OHS 管理的 Git 裸仓库，不是 GitHub 专属合同；
- 通用 `tool.scan`、`tool.sync`、`tool.remove`、`module.*` 和模块热重载能力；
- 历史版本文档中的原始 GitHub 叙述，历史事实不回写；
- 模块同步后产生的通用注册表、日志和 `Modules\GitHubConnection` 运行时事实。这些属于外部模块消费，不属于产品内置。

生产源码、现行产品装配点和 OHS 正式包中不得再出现 GitHub 专属实现。静态门禁只排除不可改写的
`b-Office/history` 历史记录。

## 外部合同

GitHubConnection 模块位于：

```text
C:\OneHistory\OneHistory-Projects\2026-019-Studio工具箱
├─ b-Code-GitHubConnection
└─ z-GitHubConnection
```

模块合同固定为：

- 模块正式名称 `GitHubConnection`，版本 `1.0.0`，命令域 `github`；
- 消费 `OneHistory.AppShell.Core 3.0.3`，不引用 OHS 源码或 AppShell 源码；
- 实现 `IUiModule + IShellUiAware`，注册稳定窗口 ID `github.account`；
- 窗口标题为“GitHub 连接”，默认停靠右侧，默认比例 `0.38`，沿用旧 ID 继承现有布局；
- 只注册 `github.status`、`github.accounts` 和 `github.test` 三条只读命令；
- 登录、注销、提交身份和 origin 修改只存在于服务器本机模块 UI，不进入 CommandRegistry、Web 或 MCP；
- manifest 使用 `ui=true`、`mcpExposure=readonly`，正式产物由 `z-GitHubConnection` 自包含提供。

客户端角色不加载模块 UI，因此客户端不再显示 GitHub 页面。Git/GCM/SSH 凭据本来位于服务器，本次把界面边界与
凭据所有权统一到服务器本机。

## OHS 实施步骤

1. 删除 GitHub 专属生产文件、`ToolProcessRunner.cs` 和对应 Smoke 文件；
2. 从服务组合根删除 GitHub 服务与七条命令，从桌面装配删除窗口和菜单动作；
3. 调整 Smoke 编排和 Docking 测试，在现有架构门禁中加入“生产域无 GitHub 专属实现”断言；
4. 更新现行使用说明、发布与升级文档及 MCP 安全文档，重新生成命令手册；
5. 将 `StudioVersion.props` 提升为 2.8.3，四个 AppShell 包继续固定为 3.0.3；
6. 完成 OHS 定向验证和发布候选验证，正式包保持不携带模块；
7. 先部署 OHS 2.8.3 清除内置命令域，再同步 GitHubConnection，避免 2.8.2 的内置 `github` 域拒绝模块注册。

- OHS 默认功能 Smoke 由 12 套降为 11 套，Debug/Release 完整门禁共 22 次；

- `tool.list`、`module.list`、Help 和 MCP 必须从同一注册表读取模块事实，不维护 OHS 专用白名单。
