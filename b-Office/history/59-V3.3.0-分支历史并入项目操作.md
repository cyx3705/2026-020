# V3.3.0 分支历史并入项目操作

> 状态：开发候选完成；不正式发布、不部署

## 目标

HistoryJanus 3.3.0 删除独立分支历史页面，模块只注册 `overview`、`projops` 两个页面；分支历史作为项目操作页的内嵌组件，与 Git 文件规则同级切换。同时修复 `2026-021-HistoryMercury` 因缺失 `config.worktree` 被 Git 误判为裸仓库导致的"读取未跟踪文件失败 / 读取已忽略文件失败"。

## 实现

- 项目操作页底部新增同级切换条（`GroupName="BottomPage"` 两段，复用分段按钮样式），默认停在"Git 文件规则"；切到"分支历史"时规则面板折叠、历史面板显示，项目与提交推送两组固定常驻。
- `ProjectOperationsView` 构造函数接收 `Func<string, bool> isProtected`，构造时以 `HistoryPanel.Content = new BranchHistoryView(...)` 内嵌历史组件；`BranchHistoryView` 文件保留，根边距 8→0 避免双重边距。
- 模块注册撤销稳定窗口 ID `history`；命令层零改动，`proj.history`、`proj.history.show`、`proj.history.diff`、`proj.rollback`、`proj.reset`、`proj.forcepush` 全部保留，31 条业务命令不变。
- 版本源、manifest、状态命令、模块 API 与现行文档更新为 `3.3.0`。

## 缺陷根因与修复

- 根因：裸仓 `HistoryVesta.git/config` 含 `bare = true` 且 `extensions.worktreeConfig = true`；健康 worktree 的 gitdir 都有 `config.worktree` 写明 `[core] bare = false`。`2026-021-HistoryMercury` 的 gitdir 缺失该文件，继承公共配置后被 `git rev-parse --is-bare-repository` 判为 true；纯索引读取 `ls-files` 已跟踪仍成功，只有 `--others` 两条命令报 `fatal: this operation must be run in a work tree`。
- 数据修复（一次性）：补写 `HistoryVesta.git/worktrees/2026-021-HistoryMercury/config.worktree`，内容与健康 worktree 逐字一致；`is-bare-repository` 恢复 false，三条 `ls-files` 均 exit 0。未采用 `git worktree repair`（只修 gitdir 路径，不补 config.worktree）。
- 诊断可行动化：`GitFileRuleService.ReadRepositoryStateAsync` 检测到 `must be run in a work tree` 时，报错指出项目路径、缺失 `config.worktree` 的 `core.bare=false` 这一原因及修复方法；读取路径不静默改写仓库元数据。
- 已知边界：`FormatInventoryService` 对同类失败维持静默容错，本轮不展开。
