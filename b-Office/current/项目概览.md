# HistoryJanus 项目概览

更新日期：2026-08-29

V5.5.0 把项目总览改为“项目 / z 级文件夹 / 最近提交 / 状态”四列，并以提交、推送、同步、
归档、拉取形成完整生命周期。一个项目可保留多个直属 z/Z 文件夹；归档只移除本地 Git 工作树，
拉取时本地 z/Z 内容优先恢复。归档项目的分支历史直接读取 GitHub 远端。

2026-08-30 开发管线验收探测。

## 一句话定义

HistoryJanus 是运行在 HistoryVulcan 中的自用项目与 Git 治理模块，按**一项目一仓**托管 HistoryClio 下全部编号项目（包括自己），并提供继承树、Meta、Git 文件规则、提交、推送、分支历史与只读提交图谱。

## 目标与边界

### 目标

- 以单个 HistoryVulcan 模块提供三个 Aurora 描述化页面和稳定命令集合；页面由 `janus.ui.describe`、`janus.ui.actions`、`janus.ui.data` 与 `janus.ui.graphnode` 投影，图谱以 `swimlane` 并入宿主 `console` 标签组。
- 4.0.0 起存储引擎为独立 git 仓（目录名 = 项目，仓内默认分支 `main`），不再使用共享裸仓 + worktree。
- 通过版本化发布区 `z-Publish/HistoryJanus-vX.Y.Z/` 交付可校验、可回滚的正式模块快照。
- 在项目操作页直接编辑当前项目名，经确认后同步改名项目展示名与工作树目录。
- 下一阶段按 [`AI开发工作流与分支图谱计划.md`](./AI开发工作流与分支图谱计划.md) 建设 AI 工作树展示；
  工作区与发布由宿主开发管线拥有，Diana 只提供文档通道。

### 范围

- `b-Code-Studio/Module` 的模块入口，以及其链接使用的项目、Git、视图和业务组合源码。
- `b-Code-Verify` 的 Contracts、功能 Smoke、模块装载和发布门禁。
- `z-Publish/HistoryJanus-vX.Y.Z/` 的当前候选，以及 `z-Publish/history` 的历史正式包。

### 非目标

- 不提供独立 `HistoryJanus.exe`、独立 ServiceHost、独立 Shell、Web/MCP 网关或开机自启动项。
- 不复制或发布 HistoryVulcan 运行库；宿主从 `2026-023-HistoryVulcan/z-Publish` 独立交付。
- 不把 Janus CLR 类型作为跨模块二进制 API；其他模块通过宿主命令总线协作。
- 本轮不改 HistoryVesta 里的旧 Janus，不注册 `janus.aiworktree.*` 写命令。

## 当前里程碑

V5.4.7 把已经进源码的 Aurora 面板协议 V3（控制面板按 `rows` 声明）和 z 目录形状
`HistoryJanus-vX.Y.Z/` 升成当前候选：发布只走宿主 `vulcan.dev.start` → `submit`（热重载送审）
→ 人审批通过后 `finish` 并回 main。Diana 不发布。命令面相对 5.4.6 不变。

V5.4.6 把 Git 文件规则 / 分支历史 / GitHub 三页**收进**「项目操作」页：控制面板加第四行
轮换选项框，转到哪个标题，下面就换成哪一块的控件（用的是 Aurora 1.8.17 的 `channel` +
`switch`）。页面从六个减到三个，底边让了出来，三块内容各自拿到整块高度。
没被切到过的那几支不取数——落地状态那一支每次跑两条 `git ls-files`，
GitHub 那一支要探 SSH 与凭据助手。

同轮删掉四页顶上那几段「这一页是干什么的」说明文字，以及面板里的说明控件。
它们占的是版面，给的是一次性的信息——每个打开这一页的人都要重新翻过去一次，
而其中内容（清单全库共用、落地状态按选中项目、历史最多 200 条）属于文档。

刷新按钮随之改为**按节点**刷：三块同处一页，按页刷会把没被点到的两块一起带上。

另外，「控件贴着窗格边框画」不在 Janus 这边——描述协议里没有任何字段能表达内边距，
已由 Aurora REQ-UI-047 在装载器一侧统一补上。

V5.4.5 把「项目操作」页重注册为一块三行控制面板（项目名/改名、新项目名/新建、
提交描述/提交·推送），Git 文件规则 / 分支历史 / GitHub 三块回归为底部标签组，
并让「项目总览」的项目表经**选择通道**驱动它们——两页各渲染一次，
页内节点 id 跨不过去，通道名跨得过去。图谱与分支历史因此跟着选中走
（图谱此前固定画项目清单第一条，不报错，只是一直不对）。需 Aurora ≥ 1.8.16。
此前该页写的是已退役的页面级 `input` + `button`，真机上是三块牌子，一个能点的东西都没有。
V5.4.4 在 Aurora 1.8.4 延迟后台取数合同上修复项目行字段投影与分支泳道首项目选择；基于 V5.4.3 适配 HistoryVulcan 5.1.2 与 Aurora 描述化页面协议 V1。
命令名、三个页面 ID 与 `name=` 仍是项目文件夹名；Git 语义按项目目录上的独立仓库重写。

## 关键约束

- 平台：Windows、.NET 8、HistoryVulcan >= 5.1.2 current-host 宿主合同、Aurora 描述化页面协议 V1；HistoryVulcan 是否洁净以其 z 快照 manifest 为准。
- 兼容性：模块名 `HistoryJanus` 和现有业务命令名保持稳定；当前 Aurora 页面 ID 为 `overview`、`graph`、`projops`；历史版本移除的 `tree`、`meta`、`history` 页面 ID 不得恢复。
- 数据：模块数据根由 HistoryVulcan `IModuleContext.DataDirectory` 提供，并在其下使用 `HistoryJanus` 子目录。
- 项目库：`proj.libraryroot` 默认 `C:\OneHistory\HistoryClio`；只扫库根直接子目录。
- 安全：MCP 只投影只读命令；写操作仍由宿主确认策略控制。
- 发布：不执行开机自启动测试，不从 Janus 包发布或启动宿主进程。
