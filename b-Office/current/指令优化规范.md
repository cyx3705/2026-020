# 指令优化规范（跨模块对齐）

> 适用范围：HistoryVulcan 外置业务模块的命令命名与目录治理。
> 首发模块：HistoryJanus 3.5.0；3.5.1 起强制 `CommandClass` 与中间段一致，并禁止残留已并入模块的独立域槽。其他模块应按本规范做同构改名，只改本模块域，不互相抢占。

## 1. 命名合同

指令名采用三段式：

```text
<模块域>.<类>.<方法>
```

示例：

| 指令 | 含义 |
| --- | --- |
| `janus.proj.list` | Janus 模块 / 项目类 / 列出 |
| `janus.history.rollback` | Janus 模块 / 历史类 / 回滚 |
| `janus.gitrule.batchset` | Janus 模块 / Git 规则类 / 批量设置 |
| `janus.github.test` | Janus 模块 / GitHub 类 / 连接检测 |
| `janus.status` | Janus 模块状态（无类时允许两段） |

规则：

1. **全小写**：域、类、方法均不得出现大写字母。禁止 `HistoryJanus.Status`、`Janus.Proj.List`。
2. **域名短拼、不带 History**：模块显示名可含 History，但命令域必须是短拼（`janus`、`mercury`、`vulcan`），避免输入负担。
3. **类是模块内细分**：同一模块下按职责拆类（本模块 3.9.0 为 `proj` / `gitrule` / `history` / `github` / `graph` 五类，DEC-012），不要把所有方法堆在一个类；但也不为一两条命令单开一个类，更不注册诊断或自动化辅助类（3.7.0 起 `meta` 并入 `proj`、`debug` 整体退役）。`aiworktree` 类名预留给后续版本，4.0.0 不得注册。
4. **`CommandClass` 必须等于命令名中间段**：宿主目录的「类」过滤读的是 `CommandClass` 字段，不是从名字解析。`janus.github.status` 的 `CommandClass` 必须是 `github`，禁止残留独立模块时代的 `connection` / `account` / `git-rules` / `projects` 等旧类名。
5. **方法名短、无连字符**：优先单词（`list`、`open`、`batchset`）；禁止 `batch-set`、`force-push`。
6. **参数 `key=value` 全小写**：`name=demo target=both`，键名不得 PascalCase。
7. **状态命令**：模块身份状态优先 `janus.status` 这种两段式；由 `[ModuleCommand]` + `CommandPrefix` 投影时，方法名本身也必须小写；`CommandClass` 用 `core`。
8. **禁止把已并入的能力再注册成独立域**：例如 GitHub 连接并入后只能是 `janus.github.*`，不得再出现 `github.*` 一级域或旧模块 `GitHubConnection`。

## 2. 注册与来源

- 组合根（如 `StudioBusinessComposition`）是业务命令的唯一注册入口；注册源统一 `module:<ModuleName>`。
- `CommandPrefix`（模块 `ModuleInfo` 上的可选属性）只影响 `[ModuleCommand]` 反射投影的域前缀，不替代组合根注册。
- 只读命令必须 `Readonly = true`；危险写操作必须带确认门（`ConfirmPrompt` / `IsDangerous`）。
- UI 写操作若刻意不进命令总线（如 GitHub 登录/注销），必须在模块 API 与架构测试中显式声明，禁止静默直连。

## 3. 破坏性改名流程

1. **一次硬切，不留别名**：旧名直接删除，不双注册，避免 MCP 目录翻倍与长期双轨。
2. **同版本完成**：命令名、视图调用点、Contracts/Smoke/ModuleSmoke、模块 API 文档必须同版本切换。
3. **历史文档不改**：`b-Office/history/*` 保留当时事实；现行合同只改 `current/` 与 `package/`。
4. **登记映射表**：在该版本历史文档中列出旧→新完整映射，供其他模块与外部脚本对齐。

## 4. Janus 3.5.0 映射（对照样板）

| 旧 | 新 |
| --- | --- |
| `HistoryJanus.Status` | `janus.status` |
| `proj.list` … `proj.config`（13） | `janus.proj.<同名>` |
| `proj.metalist` / `proj.metaopen` | `janus.proj.metas` / `janus.proj.metaopen` |
| `proj.history` / `.show` / `.diff` | `janus.history.list` / `.show` / `.diff` |
| `proj.rollback` / `.reset` / `.forcepush` | `janus.history.rollback` / `.reset` / `.forcepush` |
| `git.rule.*`（含 `batch-set`） | `janus.gitrule.*`（`batchset`） |
| `github.status/accounts/test` | `janus.github.status/accounts/test` |
| `debug.logflood/sleep` | 3.7.0 退役（日志承压改用宿主 `vulcan.log.flood`） |

设置键（如 `proj.libraryroot`）不是命令名，可不改；窗口 ID（如 `overview`、`graph`、`projops`、`github`）保持稳定，不套三段式。

## 5. 验收清单（其他模块可复用）

- [ ] 全部命令名匹配 `^[a-z]+(\.[a-z0-9]+)+$`，无大写、无连字符。
- [ ] 命令目录 Contracts 断言与运行时注册一致。
- [ ] 视图/脚本/`ExecuteAsync` 字面量旧名零残留（历史文档除外）。
- [ ] 模块 API 写明破坏性变更与完整映射。
- [ ] ModuleSmoke 覆盖状态命令、至少一类读写命令与页面构造。
