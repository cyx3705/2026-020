# HistoryJanus 验证合同

## 验证原则

- 日常开发只运行相关 Contracts、Debug 构建、定向功能 Smoke 和 ModuleSmoke。
- 正式发布运行 Debug/Release 构建、Contracts、完整功能 Smoke、ModuleSmoke、包静态门禁、checksum、双槽部署和回滚验证。
- 功能 Smoke 当前固定为 `VersionProjection`、`TestArchitecture`、`GitRules`、`BranchHistory`、`BranchGraph`、`SubmoduleSafety`、`RepositoryTargets`、`ProjectOperations` 和 `GitHub` 九套；宿主装载、卸载和热重载只由独立 ModuleSmoke 验证。
- Architecture/Contracts 将覆盖 AI 工作树状态机与 HEAD 失效规则（DEC-012），即使 4.0.0 尚未注册 `janus.aiworktree.*`。
- 正式流程不得运行或修改开机自启动，也不得替用户启动 HistoryVulcan。
- 运行时命令目录、窗口注册、module manifest 和正式包文件集合是可执行事实；文档必须与其一致。
- 产品 Git 进程不设应用级墙钟超时；宿主取消仍必须终止完整进程树。GitHub 诊断和 Smoke
  的具名超时是独立安全边界，不得随产品 Git 超时一起删除。
- 文件规则编辑期间不得调用保存命令；离页只允许一组 preview/apply，并发离页共享结果，
  失败后必须保留 dirty 数据并恢复规则分段。
- 项目总览的工作树状态必须覆盖干净、已跟踪修改、未跟踪文件和恢复干净；状态读取失败显示未知，
  不得阻断其余工作树。
- 图谱布局必须用倒序跨分支时间戳、已合并多提交越界和开放行时间跨度验证父边赋 X：开放分支首节点
  紧邻分叉点右侧，已合并历史分支同时贴住分叉与 merge；只验证节点仍在独立泳道不足以关闭该回归。
- 首次推送建远端仓库必须在门禁内**离线**验证：GitHub Smoke 用假 provisioner 和假 HTTP handler 覆盖
  建仓并推送、422 复用、建仓失败不留半配 origin、已有 origin 不触碰 provisioner 四条路径。
  门禁不得发起真实 GitHub 请求，也不得读取真实 GCM 凭据。
- `Test-QualityGate.ps1` 必须阻断根 `project.manifest.json` / `AGENTS.md` 缺失、项目身份与版本漂移，
  以及模块 API 的版本、宿主基线、窗口清单、命令总数或 z 快照副本漂移。

## 图谱布局专项

| 场景 | 夹具 | 通过标准 |
| --- | --- | --- |
| 开放分支时钟早于分叉点 | 主线 `root -> fork`，分支提交的时间早于 `fork`，但父提交是 `fork` | 分支首节点横坐标 = `fork` 右侧一个标准节点间距 |
| 已合并分支仍共享主线祖先 | 主线 `root -> main-before -> merge`，分支 `root -> base -> tip`，`merge` 第二父为 `tip` | 历史泳道末节点横坐标 = `merge` 左侧一个标准节点间距，不得优先锚定 `root` |
| 已合并多提交长于分叉到 merge | 主线 `fork -> mid -> merge`，分支 `fork -> b1..b4`，`merge` 第二父为 `b4`，分支时间戳全部早于主线 | 首节点紧邻 fork 右侧，末节点紧邻 merge 左侧；不得因整行平移而越过分叉点 |
| 开放行时间跨度大于主线 | 主线 `fork -> tip`，开放分支三提交时间戳跨数月 | 相邻分支节点间距为一个标准节点间距，行宽由提交数决定，不随时间跨度拉长 |
| 已删除已合并 ref | 删除分支 ref，仅由 merge 第二父恢复历史泳道 | 泳道仍存在、无开放 tip，且继续使用 merge 锚点 |
| 不相交已合并行 | 主线 `root -> a -> m1 -> b -> m2`，左支 `root -> left` 合入 `m1`，右支 `b -> right` 合入 `m2` | 两支都在主线下一行，不得把左支放到更低的空行 |
| 相交平行行 | 两条支线从同一分叉点出发且水平跨度重叠 | 先占用者留在主线下一行，后者下移一行 |

## 环境前提

- Windows 与 .NET 8 SDK。
- HistoryVulcan current-host 快照位于 `C:/OneHistory/HistoryClio/2026-023-HistoryVulcan/z-HistoryVulcan`；版本和 `sourceDirty` 以其 manifest 为准。
- 正式发布的源码洁净度、候选证据、促级顺序和失败回滚以 Diana 正式 `moduleDevelopment` 合同为准；
  Janus 文档不复制一套可能漂移的外部管线参数。
- 模块部署不要关闭 HistoryVulcan。管线在宿主运行时原地覆盖 z 并热重载；只有替换宿主 EXE 才停进程。

## 证据保存

| 证据类型 | 保存位置 | 是否入库 | 保留规则 |
| --- | --- | --- | --- |
| 最新正式模块及校验 | `z-HistoryJanus` | 是 | 只保留最新版本 |

| 部署回滚 | HistoryVulcan Modules 同级 `HistoryJanus-rollback-*` | 否 | 至少保留本次部署前版本 |

## 明确不执行

- 开机自启动测试。
- 自动启动 HistoryVulcan 或旧 Janus。
- 真实 GitHub 凭据修改、真实推送、UAC、防火墙和双机 LAN 测试。
