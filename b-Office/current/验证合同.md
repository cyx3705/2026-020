# HistoryJanus 验证合同

## 验证原则

- 日常开发只运行相关 Contracts、Debug 构建、定向功能 Smoke 和 ModuleSmoke。
- 正式发布运行 Debug/Release 构建、Contracts、完整功能 Smoke、ModuleSmoke、包静态门禁、checksum、双槽部署和回滚验证。
- 功能 Smoke 当前固定为 `VersionProjection`、`TestArchitecture`、`GitRules`、`BranchHistory`、`BranchGraph`、`SubmoduleSafety`、`RepositoryTargets`、`ProjectOperations` 和 `GitHub` 九套；宿主装载、卸载和热重载只由独立 ModuleSmoke 验证。
- Architecture/Contracts 将覆盖 AI 工作树状态机与 HEAD 失效规则（DEC-012），即使 4.0.0 尚未注册 `janus.aiworktree.*`。
- 正式流程不得运行或修改开机自启动，也不得替用户启动 HistoryVulcan。
- 运行时命令目录、窗口注册、module manifest 和正式包文件集合是可执行事实；文档必须与其一致。
- 产品 Git 进程不设应用级墙钟超时；宿主取消仍必须终止完整进程树。GitHub 诊断和 Smoke
  的具名超时是独立安全边界，不得随产品 Git 超时一起删除。
- 文件规则编辑期间不得调用保存命令；离页只允许一组 preview/apply，并发离页共享结果，
  失败后必须保留 dirty 数据并恢复规则分段。
- 项目总览的工作树状态必须覆盖干净、已跟踪修改、未跟踪文件和恢复干净；状态读取失败显示未知，
  不得阻断其余工作树。
- `Test-QualityGate.ps1` 必须阻断根 `project.manifest.json` / `AGENTS.md` 缺失、项目身份与版本漂移，
  以及模块 API 的版本、宿主基线、窗口清单、命令总数或 z 快照副本漂移。

## 验证层级

| 编号 | 层级 | 适用时机 | 命令或步骤 | 通过标准 |
| --- | --- | --- | --- | --- |
| VERIFY-FAST | 快速检查 | 相关功能完成 | `dotnet build HistoryJanus.sln -c Debug`；定向 Contracts/Smoke；ModuleSmoke；`b-Code-Studio/eng/Test-QualityGate.ps1` | 0 warning、0 error，选定测试全绿；API 与版本源一致、窗口 3 个、运行时命令 40 条；产品 Git 无自决超时，规则离页批量保存，总览工作树状态三态正确 |
| VERIFY-CI | 推送门禁 | 推送到 `2026-020-HistoryJanus` | `.github/workflows/historyjanus-gate.yml`：锁定还原、双配置构建、Contracts、`dotnet format` 验证、质量门禁 | 流水线全绿 |
| VERIFY-FULL | 完整回归 | 正式候选 | `../2026-019-HistoryDiana/b-Code/Publish-OneHistoryModule.ps1 -Module HistoryJanus` | Debug/Release、Contracts、功能 Smoke、ModuleSmoke 和包门禁全绿 |
| VERIFY-PUBLISH | 正式提升 | 用户显式批准 | 上述 Diana 命令加 `-Publish`；要从干净 HEAD 复现时另加 `-RequireCleanSource` | z 级正式树（含 docs）原子更新，旧正式包进入 history |
| VERIFY-ACCEPT | 人工验收 | 用户重启 HistoryVulcan 后 | 模块管理、三个页面、项目与 Meta 列举、独立分支图谱、Git 文件规则、内嵌分支历史与 GitHub 的同级切换 | 模块可见，页面功能生效，UI 与后台命令来源一致 |

## 环境前提

- Windows 与 .NET 8 SDK。
- HistoryVulcan current-host 快照位于 `C:/OneHistory/HistoryVesta/2026-023-HistoryVulcan/z-HistoryVulcan`；版本和 `sourceDirty` 以其 manifest 为准。
- 正式发布默认先部署后提交：源码可以脏，部署成功后再与 `z-HistoryJanus` 一起提交。
  只有要从干净 HEAD 复现时才给 Diana 加 `-RequireCleanSource`。
- 模块部署不要关闭 HistoryVulcan。管线在宿主运行时原地覆盖 z 并热重载；只有替换宿主 EXE 才停进程。

## 证据保存

| 证据类型 | 保存位置 | 是否入库 | 保留规则 |
| --- | --- | --- | --- |
| 最新正式模块及校验 | `z-HistoryJanus` | 是 | 只保留最新版本 |
| 被替换的正式包 | `b-Publish/history/package-*` | 否 | 只保存历史正式包，不保存构建工作区 |
| 当前候选 | `b-Publish/current/HistoryJanus` | 否 | 下一次候选原子覆盖 |
| 部署回滚 | HistoryVulcan Modules 同级 `HistoryJanus-rollback-*` | 否 | 至少保留本次部署前版本 |

## 明确不执行

- 开机自启动测试。
- 自动启动 HistoryVulcan 或旧 Janus。
- 真实 GitHub 凭据修改、真实推送、UAC、防火墙和双机 LAN 测试。
